| 预测趋势（延续） | ⭐⭐ | 有成熟方法，相对容易 |

## 3. 只需要这些数学（其余全部跳过）

**需要**（初中水平即可）：
- 平均值、标准差 —— 衡量波动大小
- 百分比变化、差分 —— 变化了多少
- 相关性 —— 两个变量是否同向
- 概率直觉 —— 输出 0.7 理解为"七成可能"

**不需要**：线性代数、微积分、矩阵求导、损失函数推导。

> LightGBM 可理解为"一个很聪明的**自动 if-else 生成器**"。

## 4. 核心：把"转折点"变成机器学习问题

这一步比调参重要 100 倍。三种做法，由易到难：

### 做法 A —— 回归（起步，先验证流程）
```
标签 = 未来 N 期的变化率
```
输出数值。简单，但对转折不敏感。

### 做法 B —— 三分类（推荐正式起点）
```
未来 N 期变化 > +阈值  → 上升
未来 N 期变化 < -阈值  → 下降
其余                   → 盘整
```
"阈值 + 盘整类"是关键：过滤噪音，让模型只在有把握时表态。

### 做法 C —— 转折点标注（最终目标）
```python
from scipy.signal import argrelextrema
# 事后标出历史局部极大/极小值 = 真实转折点
# 标签 = 当前时点是否处于转折点附近（±k 期内）
```

注意事项：
- 转折点极稀少（约 2~3%）→ **极度不平衡分类**，准确率无意义，看**精确率 / 召回率**
- 标签定义可用未来信息；**特征中绝不可含未来信息**

## 5. 六个致命陷阱（时间序列专属，请反复回看）

### 1. 数据泄漏 / 未来函数 —— 头号杀手
任何特征只能用当前及之前的数据。用 `.rolling()` 而非全局 `.mean()`，注意 `shift(1)`。

### 2. 随机划分训练集 —— 绝对禁止
```python
# ❌ train_test_split(X, y, shuffle=True)
# ✅ TimeSeriesSplit / 按时间切分
```
随机划分等于"用明天预测昨天"，结果好得离谱，上线全崩。

### 3. 没有基线对比 → 无法判断好坏
必须对比：
1. 随机漫步（明天 = 今天）
2. 趋势延续
3. 移动平均交叉

**打不过这三个，模型即无用。** 这条能省下无数无用功。

### 4. 反复调参调出的"假好结果"
在同一测试集试 200 组参数选最好的 → 那是**运气**。
留一段**从头到尾没碰过**的最终数据，全部工作完成后只测一次。

### 5. 忽略确认延迟
必须记录：**信号发出时距真实转折已过多少期。**
此指标比准确率更能说明系统价值。

### 6. 概念漂移
历史规律会失效。任何"过去 10 年回测很准"都要追问：**最近 1 年表现如何？**

## 7. 六个月计划（每天 2 小时）

### 第 1–3 周：Pandas 打通
- `read_csv`、索引切片、`groupby`、`merge`（SQL 背景上手快）
- **重点**：`DatetimeIndex`、`resample()`、`rolling()`、`shift()`、`diff()`、`pct_change()`
- 练习：取一份熟悉的历史数据，画走势图，算移动平均与波动率

> ⚠️ 80% 精力放在 `rolling` 和 `shift` —— 后续特征工程的命脉。

### 第 4–6 周：机器学习最小必要概念
- 训练 / 验证 / 测试集（**按时间切**）
- 过拟合是什么、为何可怕
- 分类 vs 回归
- 评估指标：**精确率、召回率、AUC**（理解"宁可少报还是宁可多报"）
- ⛔ 不碰数学推导

### 第 7–10 周：LightGBM 上手 + 第一个闭环
- 跑通 `LGBMClassifier` / `LGBMRegressor`
- 掌握 `early_stopping`、`num_leaves`、`learning_rate`
- 完成闭环：数据 → 特征 → 训练 → 时序验证 → **与基线对比**
- 目标不是准，是**流程正确**

### 第 11–16 周：特征工程（投入最多时间，决定成败）

把时间序列"摊平"成表格：

| 特征类型 | 例子 |
|---------|------|
| 滞后特征 | 前 1/2/3/5/10 期的值 |
| 滚动统计 | 5/10/20 期均值、标准差、最大最小 |
| 变化率 | 1 / 5 / 20 期涨跌幅 |
| 位置特征 | 在过去 20 期中的百分位、Z-score |
| 斜率 / 加速度 | 趋势方向 + **趋势的变化**（转折关键） |
| 偏离度 | 当前值 / 移动平均 − 1 |
| 波动状态 | 波动率是否在放大 |
| 时间特征 | 星期、月份、季节性 |

> 💡 **核心洞察：转折信号藏在"二阶变化"里** —— 不是"在涨"，而是"**涨得越来越慢**"。
> 斜率变化、动量衰减、波动率突变，远比原始值重要。

### 第 17–20 周：专攻转折点检测
- **`ruptures`** 库（开箱可用的 change point detection）
- CUSUM（累积和检测偏移）、HMM（状态切换 / regime）
- `argrelextrema` 标注历史拐点，训练分类模型
- 不平衡处理：`scale_pos_weight`、调整判定阈值
- **SHAP** 分析模型究竟依据什么判断转折 → 产生业务洞察

### 第 21–26 周：验证、加固、落地
- Walk-forward 滚动回测，模拟真实使用
- 分时期检验稳定性（不同年份 / 不同环境）
- 输出**概率 + 置信度**，而非硬性"是 / 否"
- 做成日常运行脚本 + 可视化报告
- 可选：Streamlit 轻量界面（半天可学）
- 可选部署形态：Python 训练并提供 API → 由现有 C#/.NET 系统调用（复用既有技能）

## 8. 两条心法

### 1. 追求"有用"，不追求"神准"
转折点检测达到 60% 精确率、提前 2–3 期给信号，即**非常有价值**。
号称 90% 准的，基本都是数据泄漏。降低期待反而更容易成功。

### 2. 让模型做"报警器"，不做"决策者"
输出"当前转折风险 = 0.73"，作为**辅助信号**，与自身业务经验结合。
比追求全自动预测靠谱得多，也更能发挥个人经验优势（你有经验，模型有算力）。

## 9. 应用场景（已确定 · 2026-07-24）

| 项目 | 内容 |
|------|------|
| 领域 | **中国 A 股**，日 K 线 |
| 时间粒度 | 日线（可用近 **20 年**，单一指数 ≈ 4,850 个交易日） |
| 目标 | 每日**盘中**判断当天是否为上涨 / 下跌转折点 |
| 序列 | 起步单一指数（建议沪深300），后续可扩为多指数面板 |

### ⚠️ 已识别的三个关键矛盾（详见专项方案文档）

1. **日 K 线无法支撑真正的"盘中"判断**
   盘中你不知道今日收盘价 / 全天最高低 / 全天成交量 → 用了就是未来函数。
   → 先做**方案 1**（今日开盘前决策，只用 t-1 及之前数据），再升级**方案 2**（分钟级数据）。

2. **数据量远小于直觉**
   20 年单一指数仅约 4,850 行；若转折点占 3%，正样本仅约 145 个。
   A 股同涨同跌，横截面样本高度相关，行数虚高。

3. **20 年跨度内制度剧变，早期规律可能完全失效**
   股改、股指期货、2015 杠杆牛、熔断、注册制、±20% 涨跌幅……
   → 必须留最近 2–3 年做纯样本外，并做分年度稳定性检验。

### 🎯 战略调整：优先攻"下跌转折点"

A 股 **T+1** 制度下，卖出信号可当日执行、买入则被锁定至次日；
且下跌伴随波动率放大、特征更显著。**做风险预警比做收益预测更务实、更易出成果。**

# 对话存档索引

> 按**每天一个文件**保存与 Kiro 的完整讨论内容。
> 目的：日后翻阅旧对话时，能在已有内容里**重新发现技术增长点**。

## 三层文档结构（各司其职）

| 层级 | 文件 | 内容 | 什么时候看 |
|------|------|------|-----------|
| **第 1 层：结论** | [../AI学习路线图.md](../AI学习路线图.md) 等方案文档 | 当前**最新**的结论与计划 | 想知道"现在该做什么" |
| **第 2 层：摘要** | [../讨论记录.md](../讨论记录.md) | 每次讨论的**成果与调整原因**（精简） | 想知道"这几个月走了什么路" |
| **第 3 层：原文** | 本目录下的日期文件 | **完整对话内容**，细节全保留 | 想重新挖掘细节、发现新增长点 |

> 💡 三层的关系：
> **第 1 层会被不断改写**（只留最新结论）；
> **第 2 层只追加不修改**（保留认知演进轨迹）；
> **第 3 层是原始素材**（永不删改，日后淘金用）。
>
> 这样设计的好处：看结论不用翻历史，回顾路径有摘要，挖细节有原文。

## 命名约定

```
docs/对话存档/YYYY-MM-DD.md
```

同一天的多次对话追加到同一文件；跨天则新建文件。

## 怎么用这些存档

**建议每 1–2 个月做一次"回看"**，问自己三个问题：

1. 当时记下的哪些点，**现在才真正看懂了**？
2. 当时判断"暂不投入"的技术，**现在条件是否已经变了**？
   （例：数据量变大了、Python 熟练了、出现了更成熟的工具）
3. 有没有当时一句带过、但**现在看来是关键**的细节？

> 这三个问题正是"从旧对话中发现新增长点"的具体方法。
> 学习早期看不懂的内容，往往在能力提升后才显出价值 —— 所以原文必须完整保留。

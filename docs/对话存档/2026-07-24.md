## 第 1 轮 · 如何学习 AI(通用路径)

**我的问题**：现在如果我想学习 AI，应怎么学习，有什么路径，需要注意什么？应向哪个方向发展？

### 核心回答

**先想清楚为什么学**，不同目标路径差别很大：

| 目标 | 侧重点 |
|------|--------|
| 应用开发者（调用 AI 做产品） | 会用 API、Prompt、框架，数学要求低 |
| 算法工程师（训练/优化模型） | 数学 + 深度学习 + 工程能力，要求高 |
| 研究者（发论文、创新） | 扎实数学 + 论文阅读 + 前沿跟踪 |
| 只是想了解/转型试水 | 先跑通几个小项目建立感觉 |

> 建议：**先从"应用"入手快速获得成就感，再决定要不要往底层深挖。**
> 很多人一上来啃数学，坚持不下去就放弃了。

**基础阶段(1–3 个月)**
- 编程：Python 必须熟练；NumPy / Pandas / Matplotlib
- 数学（按需补，别死磕）：线性代数（向量矩阵）、概率统计、微积分（导数、梯度）
- 机器学习基础概念：监督/无监督、过拟合、训练/验证/测试集划分；
  经典算法（线性回归、逻辑回归、决策树、SVM、聚类）

**核心阶段(3–6 个月)**
- 深度学习：神经网络原理、CNN、RNN/LSTM、**Transformer(重中之重)**；框架选 PyTorch
- 大模型 LLM：预训练/微调、**Prompt Engineering、RAG、Fine-tuning、Agent**；
  生态 Hugging Face / LangChain / 向量数据库
- **动手做项目(最重要)**：Kaggle、复现经典模型、端到端小应用

**需要注意的七点**
1. 别陷入"教程地狱"——看 10 门课不如做 1 个项目
2. 重实践、轻记忆——AI 工具更新极快，理解原理比背 API 重要
3. 数学量力而行——应用方向不必成为数学家
4. 学会读论文和文档——arXiv、官方文档、GitHub 是一手信息源
5. 关注工程能力——真实工作中数据处理、部署、成本优化往往比模型本身关键
6. 保持信息更新——AI 半年一大变
7. 警惕焦虑——不用追每一个新模型，打牢基础后新东西上手很快

**方向选择**：大模型应用/AI 产品开发、大模型算法训练、AI Agent、多模态 AIGC、
垂直领域 AI（AI + 医疗/金融/法律/教育）、AI 基础设施 MLOps。

> 若已有行业背景，**"AI + 你熟悉的领域"往往是最快建立差异化竞争力的路线**。

## 第 2 轮 · LightGBM 怎么学

**我的问题**：lightgbm 我想好好学习，应怎么学习？

### 核心回答

LightGBM 是微软开源的 **GBDT** 框架，在结构化/表格数据上是"神器"级别，
Kaggle 常客，工业界排序、风控、推荐里到处都是。

**前置知识（别跳过）**
1. 决策树——分裂、信息增益、基尼系数
2. 集成学习——Bagging vs Boosting
3. 梯度提升——核心思想：**用新树去拟合前面所有树的残差(负梯度)**
4. 对比 XGBoost（同类竞品，理解一个另一个就通了）

**LightGBM 的"独门绝技"（面试常问）**

| 技术 | 作用 |
|------|------|
| Histogram(直方图算法) | 连续特征分箱离散化，大幅减少计算量和内存 |
| Leaf-wise(按叶子生长) | 每次分裂增益最大的叶子，而非 XGBoost 的 level-wise；精度更高但易过拟合 |
| GOSS(单边梯度采样) | 保留大梯度样本，随机采样小梯度样本，加速训练 |
| EFB(互斥特征捆绑) | 稀疏互斥特征合并，降维加速 |
| 原生类别特征支持 | 无需 one-hot，直接指定 `categorical_feature` |

> 一句话概括：**LightGBM = 直方图 + Leaf-wise 生长 + 采样优化，所以又快又准。**

**两种 API 都要会**

```python
# Sklearn 风格(最常用，推荐入门)
import lightgbm as lgb
model = lgb.LGBMClassifier(n_estimators=500, learning_rate=0.05,
                           num_leaves=31, random_state=42)
model.fit(X_train, y_train,
          eval_set=[(X_test, y_test)], eval_metric="auc",
          callbacks=[lgb.early_stopping(50), lgb.log_evaluation(50)])

# 原生 Dataset API(性能更好、功能更全)
train_set = lgb.Dataset(X_train, y_train)
valid_set = lgb.Dataset(X_test, y_test, reference=train_set)
params = {"objective": "binary", "metric": "auc",
          "num_leaves": 31, "learning_rate": 0.05}
model = lgb.train(params, train_set, num_boost_round=500,
                  valid_sets=[valid_set], callbacks=[lgb.early_stopping(50)])
```

**必须吃透的参数（按作用分组）**

- 控制精度/复杂度：`num_leaves`（**最关键**，理论上 ≤ 2^max_depth）、`max_depth`、
  `min_child_samples` / `min_data_in_leaf`
- 控制学习过程：`learning_rate`、`n_estimators`（配合 early_stopping）
- 防过拟合：`feature_fraction`（列采样）、`bagging_fraction` + `bagging_freq`（行采样）、
  `lambda_l1`、`lambda_l2`

**调参顺序**
```
先定 learning_rate(如 0.05) + 大 n_estimators + early_stopping
→ 调 num_leaves / max_depth
→ 调 min_child_samples 防过拟合
→ 调采样和正则参数
→ 最后降 learning_rate 再拉大 n_estimators 冲精度
```
可用 **Optuna** 自动调参（官方还有 `optuna.integration.lightgbm` 集成）。

**进阶主题**：特征重要性 + SHAP、类别特征处理、不平衡数据（`is_unbalance` /
`scale_pos_weight`）、自定义损失、排序任务 `lambdarank`、GPU 加速、`lgb.cv()`、模型保存部署。

**注意事项**
1. **别把 `num_leaves` 设太大**——新手过拟合的头号原因
2. 一定用 early stopping
3. 小数据集容易过拟合，更要注意正则和 `min_data_in_leaf`
4. **理解原理比背参数重要**——知道每个参数"控制什么"，调参才有方向感

**资源**：[官方文档](https://lightgbm.readthedocs.io)、GitHub `examples/`、
原论文《LightGBM: A Highly Efficient Gradient Boosting Decision Tree》(NeurIPS 2017)、Kaggle Notebooks。

## 第 3 轮 · 如何学习 AI(结合 LightGBM 兴趣重答)

**我的问题**：（重复第 1 轮问题）

### 核心回答：AI 其实有两条主线

很多人学 AI 一团乱，是因为没意识到这是**两个不同的世界**：

| | 传统机器学习(表格数据) | 深度学习 / 大模型 |
|---|---|---|
| 代表技术 | LightGBM、XGBoost、随机森林 | Transformer、LLM、CNN |
| 数据形态 | 数据库里的表、业务数据 | 文本、图像、语音 |
| 数学门槛 | 中（能理解梯度即可） | 高 |
| 企业落地 | 风控、预测、评分、排序 | 问答、文档处理、Agent |

> **最优策略：以「表格 ML」为切入点建立信心和产出，同时并行学「LLM 应用」。**
> 两条线在企业里都极其实用，且都不要求成为数学家。

**阶段化路径**
- 阶段 0（2–4 周）：Python 熟练；**Pandas/NumPy —— 把它当成"内存里的 SQL"**，
  `groupby`/`merge` 与 SQL 的 `GROUP BY`/`JOIN` 几乎一一对应，这是 SQL 背景者的天然优势
- 阶段 1（1–2 个月）：ML 核心概念、评估指标（**必须理解业务含义**）、算法到 GBDT、
  **特征工程**（表格 ML 里最值钱的技能）
- 阶段 2：**第一个真实项目** —— 不要停在 Titanic，直接从自己的业务数据入手
- 阶段 3（2–3 个月）：深度学习 + Transformer + LLM 应用四件套（Prompt/RAG/微调/Agent）
- 阶段 4：工程化落地 —— Python 训练模型 → 暴露成 API → C# 系统调用，
  这是很多企业真实的 AI 落地形态

**方向优先级建议**
1. 强烈推荐：AI + 企业业务（垂直落地）——**护城河最深，竞争最小**
2. 强烈推荐：大模型应用 / AI Agent —— 风口大、门槛不高
3. 可考虑：数据科学 / 表格建模；AI 基础设施 MLOps
4. 慎入：算法研究 / 模型训练（高薪但门槛极高）

> **定位不是"再造一个算法工程师"，而是"能把 AI 真正塞进企业业务里的人"。**
> 后者在市场上其实更稀缺。

## 第 4 轮 · 披露个人条件 → 定制方案

**我的情况**：55 岁；会一点 Python；大学数学全忘；想做应用开发；每天最多 2 小时；
目标是**用 AI 根据表格化数据预测趋势，更重要的是判断当下是不是趋势的转折点**。

### 核心回答

**难度诚实评估**

| 目标 | 难度 | 说明 |
|------|------|------|
| 预测趋势（延续） | ⭐⭐ | 相对容易，有成熟方法 |
| **判断当下是转折点** | ⭐⭐⭐⭐⭐ | 时间序列里最难的问题之一 |

> **根本矛盾：转折点只有在事后才能确认。**
> 当下看到的"疑似转折"，和噪音波动长得一模一样。
> 这个矛盾无法完全消除，只能在**及时性**和**准确性**之间做权衡。
> 想清楚这一点，就已经超过 90% 的初学者。

**三个"劣势"，两个不是问题**

1. **55 岁 —— 不是问题，反而是优势。** 应用开发拼的是耐心、系统性、对业务的理解，
   不是智力峰值。年轻人写代码快，但往往对数据背后的含义没感觉。
2. **数学忘光 —— 90% 不需要补。** 实际只需要：平均值、标准差、百分比变化/差分、
   相关性、概率直觉。**不需要**线性代数、微积分、矩阵求导、损失函数推导。
3. **每天 2 小时 —— 完全够。** 2h/天 ≈ 14h/周 ≈ 一年 700 小时，足够做出能用的系统。
   关键是别浪费在错误方向上。

**技术地图（照着搜就行）**

| 需求 | 技术术语 | 工具 |
|------|---------|------|
| 表格数据建模 | Tabular ML / GBDT | LightGBM |
| 时序特征构造 | Lag / Rolling Features | Pandas |
| 趋势预测 | Time Series Forecasting | LightGBM, Prophet(基线) |
| **转折点检测** | **Change Point Detection / Regime Shift Detection** | **ruptures**, CUSUM, HMM |
| 找历史高低点 | Local Extrema / Zigzag | `scipy.signal.argrelextrema` |
| 正确验证 | Walk-Forward Validation | `TimeSeriesSplit` |
| 模型解释 | Explainability | SHAP |

**核心：把"转折点"变成机器学习问题**（比调参重要 100 倍）

- **做法 A 回归**：标签 = 未来 N 期变化率。简单，但对转折不敏感
- **做法 B 三分类（推荐起点）**：
  ```
  未来 N 期变化 > +阈值 → 上升
  未来 N 期变化 < -阈值 → 下降
  其余                  → 盘整
  ```
  "阈值 + 盘整类"是关键：过滤噪音，让模型只在有把握时表态
- **做法 C 转折点标注**：用 `argrelextrema` 事后标出历史局部极值 = 真实转折点。
  ⚠️ 转折点极稀少（2–3%）→ **极度不平衡分类**，准确率无意义，看精确率/召回率。
  ⚠️ 标签可用未来信息；**特征绝不可含未来信息**

### 🚨 六个致命陷阱（时间序列专属，90% 的人死在这里）

1. **数据泄漏 / 未来函数（头号杀手）**——特征里用到未来信息。
   如用整个数据集算平均值做标准化。铁律：只能用当前时点及之前的数据，
   用 `.rolling()` 而非全局 `.mean()`，注意 `shift(1)`
2. **随机划分训练集（绝对禁止）**——`train_test_split(shuffle=True)` 等于
   "用明天的数据预测昨天"，结果好得离谱，上线全崩。必须 `TimeSeriesSplit`
3. **没有基线对比**——AUC 0.68 好不好？不知道，除非和最笨的方法比过：
   ① 随机漫步（明天=今天）② 趋势延续 ③ 均线交叉。
   **打不过这三个，模型就是没用的**，这一条能省下无数无用功
4. **反复调参调出来的"好结果"**——在同一测试集试 200 组参数选最好，那是**运气**。
   留一段从头到尾没碰过的最终数据，只在全部工作做完后测一次
5. **忽略"确认延迟"**——若需看到转折后 5 期才能确认，实战中就晚了 5 期。
   必须记录：信号给出时距真实转折过了多久。**这个指标比准确率更能说明有没有用**
6. **分布会变（概念漂移）**——任何"过去 10 年回测很准"的模型，
   都要问：**它在最近 1 年表现如何？**

### 明确不学（省时间）

❌ 深度学习（CNN/RNN/LSTM/Transformer）——**表格和中小规模时序上通常打不过 LightGBM**，
且难调、难解释、耗算力
❌ 手推数学公式、反向传播 ❌ 大模型微调 ❌ 图像/语音/NLP
❌ ARIMA 数学理论（平稳性检验、ACF/PACF）——知概念即可
❌ 各种花哨新框架

> **唯一路线：Pandas + LightGBM + 正确的验证方法 + 特征工程。窄而深。**

### 六个月计划（初版）

第 1–3 周 Pandas（**80% 精力放 `rolling` 和 `shift`**）→ 第 4–6 周 ML 最小概念 →
第 7–10 周 LightGBM 闭环（目标不是准，是**流程正确**）→
第 11–16 周 **特征工程（投入最多时间，决定成败）** →
第 17–20 周 转折点检测专项 → 第 21–26 周 验证加固落地

**特征工程八类**

| 类型 | 例子 |
|------|------|
| 滞后特征 | 前 1/2/3/5/10 期的值 |
| 滚动统计 | 5/10/20 期均值、标准差、最大最小 |
| 变化率 | 1/5/20 期涨跌幅 |
| 位置特征 | 过去 20 期百分位、Z-score |
| **斜率/加速度** | 趋势方向 + **趋势的变化**（转折关键） |
| 偏离度 | 当前值 / 移动平均 − 1 |
| 波动状态 | 波动率是否放大 |
| 时间特征 | 星期、月份、季节性 |

> 💡 **核心洞察：转折点的信号往往藏在"二阶变化"里** —— 不是"在涨"，
> 而是"**涨得越来越慢**"。斜率的变化、动量的衰减、波动率的突变，比原始值本身重要得多。

### 两条心法

1. **追求"有用"，不追求"神准"**——60% 精确率、提前 2–3 期给信号已非常有价值。
   任何号称 90% 准的，基本都是数据泄漏
2. **让模型做"报警器"，而不是"决策者"**——输出"转折风险 = 0.73"作为辅助信号，
   与自身业务经验结合。这比追求全自动更靠谱，也更能发挥经验优势

## 第 7 轮 · 场景确定为 A 股日 K 线 ⭐ 关键转折

**我的输入**：要预测中国股市日 K 线数据，希望每天盘中判断当天是下跌或上涨的转折点，
可用前 20 年数据训练。

### 🚨 三个致命矛盾

#### 矛盾 1：日 K 线撑不起"盘中判断"

日 K 线 = 一天一行。但盘中（如 14:00）你**不知道**今日收盘价、全天最高/最低、全天成交量。

> **只要特征里用了这些，就是未来函数。回测惊艳、实盘归零，90% 源于此。**
> 很多人做出 AUC 0.85 的"神模型"，本质就是偷看了当天收盘价。

必须二选一：
- **方案 1**：今日开盘前决策，只用昨收及之前 —— ✅ 先做
- **方案 2**：真正盘中，需分钟级数据 —— 后续升级

方案 1 的代码在方案 2 中可复用 90%，不是弯路。

#### 矛盾 2：数据量比想象中小得多

| 口径 | 数量 |
|---|---|
| 单一指数 20 年 | ≈ **4,850 个交易日** |
| 若转折点占 3% | 正样本仅约 **145 个** |

> **A 股同涨同跌。** 5000 只股票在同一天的涨跌**不是 5000 个独立样本** ——
> 横截面相关性极高，有效独立信息可能只相当于几百个"市场级事件"。
> 用全市场堆出 2400 万行，置信度并不会提高。

→ 起步用**指数**（沪深300）：噪音小、无个股黑天鹅、无退市问题。

#### 矛盾 3：20 年里制度剧变

股权分置改革(2005–07)、2010-04 股指期货推出、2015 杠杆牛+股灾、2016-01 熔断(4天即停)、
2019-07 科创板 ±20%、2020-08 创业板 ±20%、注册制、机构化。

> **2006 年的规律对 2026 年可能完全无效。**

硬性要求：留最近 2–3 年做**从未参与调参**的最终样本外；分段检验
（2010–14 / 2015–18 / 2019–22 / 2023–今）；**若只在早期有效、近年失效 → 判定失败**。

### 🎯 战略调整：优先攻"下跌转折点"

A 股 **T+1**：当日买入，次日才能卖。

| 信号 | 能否当日执行 |
|---|---|
| **下跌转折**（卖出/减仓） | ✅ 可以（持仓非今日买入） |
| **上涨转折**（买入） | ⚠️ 买入即锁定至次日，承担隔夜风险 |

三个理由：
1. T+1 下卖出信号**当日可兑现**，买入信号打折
2. **规避损失的确定性，高于追逐利润**
3. 下跌常伴随**波动率放大**，特征更显著，模型更容易学到

> **把定位从"预测涨跌"改成"风险预警"。** 务实得多，也更容易出成果。

### A 股特有的隐蔽陷阱

1. **前复权价格本身就是未来函数** ⭐（极隐蔽）——前复权价会随未来的分红送股而变化，
   用今天下载的前复权数据回测 2015 年，等于把 2015 年之后的信息塞进了当时的价格。
   ✅ **正确做法：用后复权，或复权因子当时点还原**
2. **涨跌停 → 信号无法执行**——涨停买不进、跌停卖不出，模型最需要行动时恰好不能动
3. **交易成本约 0.1%（往返）**——佣金 + 卖出印花税 0.5‰ + 过户费。
   若信号只能捕捉 0.3% 的波动，扣成本后基本无意义
4. 停牌数据空洞、幸存者偏差、ST 涨跌幅不同、必须用真实交易日历
5. **验证必须 purge + embargo**——标签用了未来 N 日数据，训练集末端必须剔除重叠 N 天
   并留隔离带；同一交易日的横截面样本必须在同一折内

### 标签设计（推荐起点）

```
未来 N 日累计收益 > +阈值 → 上升
未来 N 日累计收益 < -阈值 → 下降
其余                      → 盘整
```
- N 取 **3 或 5**（1 日噪音太大，20 日太远）
- 阈值用 **1.0 × 近20日波动率 × √N**，而非固定百分比
- 进阶：ZigZag 摆动点标注 → 三重障碍法(Triple Barrier)

### 现实的成功标准

| 指标 | 及格线 |
|---|---|
| AUC | **0.54 – 0.58**；⚠️ **> 0.65 请立刻排查泄漏** |
| 下跌转折精确率 | 55% – 60% 已很有价值 |
| 确认延迟 | ≤ 2–3 日 |
| 概率分层单调性 | 必须单调（**比 AUC 更可信**） |
| 近 3 年 | 不明显衰减 |
| 扣成本后 | 优于买入持有 |

必须打过的基线：永远预测盘整、随机漫步、趋势延续、均线交叉、买入并持有。

### 方案 1 评价：思路正确，有三个天然优势

| 优势 | 说明 |
|---|---|
| ✅ 无未来函数 | 9:25 开盘价确实已知，合法 |

> "用收盘价算信号、假设按收盘价成交，实际根本来不及"。这个设计天然规避了。

### 🚨 必须修正的致命细节：训练-推理一致性

"以**每个转折点**的开盘价当作收盘价"存在歧义。

**❌ 若只对转折点那天做替换：**

| 样本 | 当日振幅 | 当日实体 |
|---|---|---|
| 转折点日 | **恒为 0** | **恒为 0** |
| 非转折点日 | > 0 | > 0 |

> 🚨 模型只要看一眼"今天振幅是不是 0"，就能 **100% 认出标签**。
> AUC 接近 1.0，你会以为找到了圣杯 —— 实盘一分钱赚不到。
>
> 这叫**标签通过特征分布反向泄漏**。比普通未来函数更阴险，因为
> **它根本没用到任何未来价格**，查一百遍价格都查不出问题。

**✅ 正确做法：每一天都是决策日，一律同样处理**

```
对第 t 日:
  特征 = f( t-1 及之前的完整日K线,
            第 t 日开盘价,
            第 t 日集合竞价成交量,
            隔夜外部信息 )
  标签 = g( t 日之后 N 日走势 )    ← 只有标签能用未来
```

**三个自检手段（务必写进代码）**
1. **断言**：所有样本满足 `high == low == close == open`
2. **泄漏探针** ⭐：只用"当日 bar 派生特征"训练一个模型，**AUC 应 ≈ 0.5**
3. **分布对比**：训练集特征分布 vs 最近实盘特征分布，不应有系统性偏移

### 方案 1 的四点改进

**① 别算当日 K 线形态特征（它们全是 0）**

因为 `O=H=L=C`，振幅、实体、上下影线**恒等于 0**，是无信息常量。改成：

| 今开 / MA5、MA20、MA60 | 是否跌破关键均线 |
| 跳空幅度 ÷ 近20日波动率 | 标准化后可跨时期比较 |
| 连续跳空方向 | 连续几日同向跳空 |

**② 集合竞价成交量 —— 被浪费的金矿 ⭐⭐**

**③ 隔夜外部信息（9:25 前全部已知，合法）**

```python
# 1. 5 日均线
df["ma5"] = df["close"].rolling(5).mean()

# 2. 昨天的 5 日均线 —— 防泄漏标准写法
df["ma5_prev"] = df["close"].rolling(5).mean().shift(1)

# 3. 二阶变化：趋势在加速还是减速 ⭐ 本项目的核心
df["ret5"] = df["close"].pct_change(5)      # 5 日收益
df["ret5_chg"] = df["ret5"].diff(5)         # 收益的变化 = 动量的变化
```
> 💡 **第 3 行就是「涨得越来越慢」的数学表达。理解它，就理解了本项目的核心思想。**

**Pandas 五个必踩的坑**

3. `inplace=True` 官方已不推荐，统一用赋值
4. **索引自动对齐** —— 两个 Series 相加会按索引对齐，索引不同会产生 NaN

不要把它当成第三门课（Python → Pandas → NumPy），那样会拖慢进度。

**实际会用到的只有七个**

| 用法 | 干什么 | 用在哪 |
|------|--------|--------|
| **`np.where`** | 条件赋值（≈ SQL 的 `CASE WHEN`） | ⭐ **三分类标签，必用** |
| `np.nan` | 缺失值 | 到处 |
| `np.sqrt` | 开方 | 波动率换算（√N 阈值） |
| `np.log` | 对数 | 对数收益率 |
| `np.sign` | 取符号 | 判断方向 |
| `np.clip` | 截断极值 | 异常值处理 |
| `.to_numpy()` | 转数组 | 喂给 LightGBM |

**本项目会真实写出的代码（第 16 周左右）**

```python
import numpy as np

fwd_ret = df["close"].pct_change(5).shift(-5)          # 未来 5 日收益（标签可用未来）
vol = df["close"].pct_change().rolling(20).std()        # 近 20 日日波动率
thr = 1.0 * vol * np.sqrt(5)                            # 波动率自适应阈值

df["label"] = np.where(fwd_ret >  thr,  1,              # 上升
                np.where(fwd_ret < -thr, -1,             # 下降
                                          0))            # 盘整
```

> 整段代码里 NumPy 只出现两次。**这就是所需的 NumPy 水平。**
> SQL 类比：`np.where(条件, 真值, 假值)` = `CASE WHEN ... THEN ... ELSE ... END`

**明确不学**：多维 ndarray、reshape/transpose/axis 操作、**广播机制细节**、
`np.linalg`、随机数高级用法、结构化数组、`np.einsum`
（这些给做图像/深度学习/数值计算的人用，做表格数据一辈子用不上）

**⭐ 唯一真正重要的概念：向量化思维**

```python
# ❌ 循环写法（C# 习惯，几万行会慢到无法接受）
returns = []
for i in range(1, len(prices)):
    returns.append(prices[i] / prices[i-1] - 1)

# ✅ 向量化写法（一行，快几百倍）
returns = df["close"].pct_change()
```

> 看到自己在用 for 循环遍历数据行，就该停下来问：有没有向量化写法？
>
> 这不只是风格问题，而是**本项目的实际约束**：方案 2 要 2 分钟扫 5000 只股票，
> **只有向量化才做得到**。

**时间安排**：穿插在第 3–6 周 Pandas 阶段，遇到就查。优先级远低于 `shift`/`rolling`/`diff`。

## 第 12 轮 · 指标热力图是「河流图」吗？

**我的输入**：股票用日 K 线生成的指标，我曾经生成了 100 多种，再经过比较，
选出对判断下跌转折点贡献最大的 150 个。我想利用视觉效果进行判断，类似 CNN，
所以我将指标归一化以后，横向是日期纵向是指标的叠加，形成了一层一层的条带的指标叠加，
这种叠加图应该叫做河流图，对吗，我觉得挺有用的。

### 术语纠正：严格说不是河流图

| | **河流图 / 主题河流图**<br>(Streamgraph / ThemeRiver) | **热力图**<br>(Heatmap) |
|---|---|---|
| 数值编码 | **条带厚度** | **颜色深浅** |
| 纵轴含义 | 堆叠累加，基线流动 | 每行一个指标，位置固定 |
| 适用 | 构成比例随时间变化 | 矩阵随时间变化 |

**对本项目必须用热力图。** 三个理由：
1. **基线漂移（baseline distortion）**——堆叠图中上层指标位置会被下层波动推动，
   指标数值未变但视觉上上下跳动，跨指标/跨时间比较在视觉上失效
2. **厚度比颜色更难读**——人眼判断细带厚度精度远低于颜色，150 条带尤甚
3. **喂给模型时河流图是失真的**——渲染成像素后是非线性变形的数据；
   热力图是**原始矩阵的直接映射**，信息保真

**正确叫法**
- **特征矩阵 / 时间-特征热力图**，形状 = `[150 指标 × N 天]`
- 信号处理同类图：**语谱图 / 频谱图（spectrogram）**
- 研究方向：**时间序列图像化（Time Series Imaging, TS2I）**

> GAF（Gramian Angular Field）、MTF、递归图都是把**单变量**序列变成图。
> 本项目有 150 个变量，`[通道 × 时间]` 直接排布**反而更自然、信息更无损**。
> **这一步的选择是对的，不需要改成 GAF。**

### 🚨 两个高度可疑的泄漏（最高优先级）

**泄漏 1：归一化是否用了全历史范围？**

```python
# ❌ 全历史归一化 = 未来函数
z = (x - x.mean()) / x.std()
z = (x - x.min()) / (x.max() - x.min())

# ✅ 因果归一化（滚动窗口）
z = (x - x.rolling(250).mean()) / x.rolling(250).std()
```

> 若用全历史归一化，2010 年某天的数值里**含有 2025 年极值的信息**。
> 且对视觉也有影响：**全局归一化的图看起来更漂亮整齐 —— 恰恰因为它偷看了未来。**

**泄漏 2：150 个指标是否在全部数据上筛选？⭐ 更隐蔽、更可能已发生**

> 若用全部 20 年数据筛选，则测试集信息已通过"哪些指标被选中"这个决策泄漏。
> 这叫 **特征选择偏差（feature selection bias）**。
> 可怕之处：**留出测试集也发现不了**，因为测试集本身参与了特征选择。

正确做法（二选一）：
- 特征选择放在**每一折的训练集内部**独立进行
- 或只用**最早一段数据**（如 2006–2015）筛选，之后**永久冻结**

**立即可做的检验** ⭐
> 用 2010–2018 选一次排名，用 2019–2025 再选一次。
> **若"最重要指标"差别很大 → 筛选结果基本是噪音。** 半小时可完成。

### 新识别的问题：150 个指标高度共线

全部派生自同一份 OHLCV → 不是 150 个独立信息源，真实独立维度可能仅 **10–20 个**。

后果：同族指标（各周期 RSI、各种均线偏离度）**互相抢功劳** →
特征重要性排名**极不稳定**，换随机种子就变 → "选出贡献最大的 N 个"本身不可靠。

应对：**相关性层次聚类**，150 → 20–30 族，每族选代表或做组级 SHAP。

> 💡 顺带解决可视化问题：**热力图的行顺序必须按聚类排列。**
> 随机顺序看不出东西；聚类排序后同族指标相邻，**"条带"结构才会真正显现**，
> 肉眼才能看出"某一整族指标同时变色"。

### 核心建议：热力图当「诊断仪表盘」，不当模型输入

**为什么不建议直接上 CNN**

| 本项目数据 | CNN 需求 |
|---|---|
| 4,850 天，转折点正样本约 **145 个** | 通常需数千至数万 |
| 单张图 150×N | 即使很小的 CNN 也有上万参数 |

> **145 个正样本训 CNN → 必然背下训练集。** 不是调参能解决的。

研究印证：有基准显示 Transformer 类在**每类训练样本极少**时表现不佳；
"理性检验"研究发现**表格模型在 UCR/UEA 中约 19% 单变量 / 28% 多变量数据集上超过 ROCKET 家族**
→ 说明"表格化 + GBDT"绝非低级方案。

**改为四轨道对照面板**
```
┌──────────────────────────────────┐
│  热力图 [150 指标 × 时间]          │  ← 行按聚类排序
├──────────────────────────────────┤
│  价格走势                          │
├──────────────────────────────────┤
│  真实转折点（事后标注）             │
├──────────────────────────────────┤
│  模型输出的转折概率                 │
└──────────────────────────────────┘
```
四者对照 → 一眼看出模型在哪些转折上抓到了、漏了、误报了。

**更值得做：SHAP 热力图** ⭐ **金矿**
同样 `[150 指标 × 时间]` 布局，但**颜色 = SHAP 值**（该指标在该天对预测的贡献）
→ 直接看到**模型在什么时候依赖哪些指标**，信息量远超静态特征重要性排名。

> **人眼在这里的正确用途是"审查模型判断"，而不是"替代模型判断"。**

### ⚠️ 风险提示：「我觉得挺有用」是危险信号

> **人眼极善于在噪音中发现模式**（空想性错觉 / apophenia）。
> 能在历史图上"看出"转折前的征兆，很可能是因为**已经知道那里是转折点**。
> 这是后见之明，不是预测能力。

**盲测方案 ⭐ 现阶段性价比最高的一件事**
1. 随机挑 50 个时间点
2. 每次**只显示截止那一天**的热力图，后续走势完全遮住
3. 判断"这里是不是下跌转折点"，记录答案
4. 全部完成后揭晓，统计准确率与误报率

判读：显著高于随机基准 → **视觉方法确有信息，值得做成模型**；不显著 → 是后见之明，及时止损。

> 不需要任何机器学习就能验证这套方法有无真信号，且本身是很好的 Matplotlib 练习。

### 若确实要用卷积/形状思想 → 用 ROCKET，不用 CNN

**ROCKET / MiniRocket / MultiRocket**：大量**随机卷积核**提取特征 + **线性分类器**。

| | CNN | ROCKET 家族 |
|---|---|---|
| 需训练参数 | 上万~百万 | **仅线性层** |
| 训练速度 | 慢 | **快几个数量级** |
| 小样本稳健性 | 差 | **好得多** |
| 多变量支持 | 是 | 是 |

- MultiRocket 比 MiniRocket 更准，可与 HIVE-COTE 2.0 竞争且快几个数量级
- 有基准显示 ROCKET 在多数据集上精度最稳定
- 库：`sktime` / `aeon`

⚠️ **对本项目的具体警告**
> 同一基准发现 **ROCKET 性能会随通道数非常多而下降。**
> **本项目有 150 个通道 —— 正好落在这个弱点上。**
→ 必须先聚类降到 20–30 个代表再考虑 ROCKET。

## 2. 归一化泄漏：确认并修复

### 2.1 影响

全历史归一化意味着每一天的数值都掺入了此后才发生的事实
（最大值、最小值、均值、标准差都来自全部 20 年）。
→ 此前所有基于该图的视觉结论，可信度需重新评估。

### 2.2 三个修复方案

```python
# 方案 1：滚动 z-score（250 个交易日 ≈ 1 年）
z = (x - x.rolling(250).mean()) / x.rolling(250).std()

# 方案 2：扩展窗口 z-score（用至今为止的全部历史）
z = (x - x.expanding(min_periods=250).mean()) / x.expanding(min_periods=250).std()

# 方案 3：滚动百分位排名 ⭐ 推荐
pct = x.rolling(250).rank(pct=True)      # 结果天然落在 0~1
```

### 2.3 为什么推荐方案 3（滚动百分位排名）

| 优点 | 说明 |
|---|---|
| **天然有界 [0,1]** | 要映射到颜色与气泡大小**必须有界**，否则极端值毁掉整张图配色 |
| **对异常值免疫** | 金融数据厚尾严重；z-score 遇暴跌日可飙至 ±8，把其余日期压成一片灰 |
| **跨指标可比** | 不同指标量纲差异极大，百分位天然统一 |
| **语义清晰** | "该指标现处于过去一年的 95% 分位" —— 一句话说得清 |

> 对**可视化用途**，滚动百分位排名几乎是最优选择。

### 2.4 ⚠️ 心理准备

改为滚动归一化后，**图会变得没那么整齐漂亮**。

> 这是**正常且正确的**。此前的整齐来自偷看未来。**丑一点的图才是真实的样子。**

## 3. 「指标计算」与「指标筛选」是两件不同的事

用户回答第二问时答的是计算方式，需区分：

| | 指标**计算**（computation） | 指标**筛选**（selection） |
|---|---|---|
| 例子 | MA20 = 过去 20 天均值 | 从 100 多种里挑出"贡献最大的 150 个" |
| 用户做法 | 只用过去 20 天 | ⏳ 待确认 |
| 判定 | ✅ **完全正确，标准的因果计算** | ⚠️ 若用了全部 20 年 → 泄漏 |

### 3.1 待确认的问题

> **做那次"比较、挑选"时，用的是哪些年份的数据？**

- 全部 20 年（2006–2025）→ ⚠️ **特征选择泄漏**
- 只用前段（如 2006–2015），后段未参与 → ✅ 干净

### 3.2 为什么这是泄漏（类比说明）

> 假设 RSI-12 在 2020–2022 恰好很灵（纯属巧合）。
> 用全部数据比较后发现它"贡献大"，于是选中。
> 再拿 2020–2022 当测试集 —— **但它之所以被选中，正是因为在这段数据上表现好。**
>
> 相当于：**考完试后按分数给学生排座位，然后宣布"我发现前排的学生成绩好"。**

### 3.3 另一个待澄清的数字

用户称"生成了 100 多种，选出 150 个" —— **150 > 100**。

推测实际是：**100 多种指标类型 × 不同周期参数 = 几百个，再从中挑出 150 个。**

若如此，则印证第 10.4 节判断：**150 个中含大量"同族不同周期"，周期维度是现成的。**

## 4. Z 轴按「与转折日贴合度」排序 —— 陷阱与合法版本

### 4.1 陷阱

用户设想："Z 轴越靠近零，指标波动与下跌转折日的贴合度越高。"

> **这个排序用到了"下跌转折日"这个标签 —— 即未来信息。**
>
> 后果：会在 Z=0 附近看到**极其漂亮、极其明显**的模式。
> 但那不是数据的规律 —— **那是按答案排出来的**。
> **这张图变成了"答案的可视化"，而不是"数据的可视化"。**

这与第 3 节的特征筛选泄漏是**同一个错误的两种形式**：都让"答案"参与了"输入"的构造。

### 4.2 合法版本（保留想法，加一道纪律）⭐

```
1. 只用训练期（如 2006–2015）计算"贴合度"，确定 Z 轴排序
2. 冻结这个排序，永不修改
3. 在 2016–2025 上画图，检查该排序是否仍然成立
```

**判读**
- 后期仍是"靠近 Z=0 的指标最贴合转折" → ✅ **真规律，且这是很强的证据**
- 后期完全乱了 → ❌ 该排序是对训练期噪音的过拟合

> **这个检验本身就极有价值**，直接回答"这套指标有没有稳定的预测力"。

## 5. 如何衡量两条指标曲线的相似度

### 5.1 四种度量（按适用度排序）

| 方法 | 说明 | 适用性 |
|---|---|---|
| **斯皮尔曼秩相关（Spearman）** | 看单调关系，对异常值稳健 | ⭐ **首选**，金融数据厚尾 |
| 皮尔逊相关（Pearson） | 最基础，看线性同步 | 🟡 可用，易被极端值带偏 |
| **带时滞的互相关** | 允许两条曲线错开几天再比 | ⭐ **对本项目特别重要** |
| DTW（动态时间规整） | 允许时间轴伸缩 | 🟢 更强但慢，后期再试（`tslearn` / `dtaidistance`） |

### 5.2 ⭐ 为什么「带时滞的互相关」特别重要

要观察"波沿 Z 轴传播"，而**传播的本质就是时滞**。

> 两个指标可能高度相似，但**错开 3 天**。
> 普通相关系数会算出"不太像"，而实际上它们是同一个信号的先后两拍。

正确做法：
- 相似度 = **最优时滞下的相关系数**
- 同时记录**最优时滞是多少天** ← 该数值本身就是"传播速度"特征

## 6. 「把相近的曲线移在一起」的标准答案

**层次聚类 + 最优叶序（optimal leaf ordering）。**

```python
import numpy as np
from scipy.cluster.hierarchy import linkage, leaves_list
from scipy.spatial.distance import squareform

# ⚠️ 只用训练期数据！
train = df_indicators.loc["2006":"2015"]

# 1) 算相似度 → 转成"距离"
corr = train.corr(method="spearman")          # 150 × 150
dist = 1 - corr.abs()                          # 相关性绝对值大 → 距离近
np.fill_diagonal(dist.values, 0)

# 2) 层次聚类，optimal_ordering 是关键
Z = linkage(squareform(dist.values, checks=False),
            method="average",
            optimal_ordering=True)             # ⭐ 关键参数

# 3) 拿到排好的顺序
order = leaves_list(Z)
sorted_names = train.columns[order]            # 即 Z 轴顺序
```

> **`optimal_ordering=True` 就是"把相近的曲线移在一起"的答案。**
> 它在保持聚类结构的前提下旋转树的每个分支，
> 使**相邻叶子之间的距离尽可能小** → 相似指标自动相邻，整条 Z 轴平滑过渡。

**两个技术细节**
- 用 `corr.abs()`：**完全负相关的两个指标其实是同一个信息**（取负号即相同），应排在一起
- 展示时可在每族内统一符号（以族内第一个为基准），避免视觉上红蓝互相抵消

### 6.1 其他可选排序方法

| 方法 | 说明 |
|---|---|
| **谱排序（spectral seriation）** | 用相似度矩阵的第二特征向量（Fiedler 向量）排序 |
| **一维降维** | 用 MDS / UMAP 降到 1 维后按该值排序 |

两者更"数学"，但层次聚类 + `optimal_ordering` 通常够用且更好解释。

## 7. ⭐⭐ 推荐方案：Z 轴两级排序

```
主序：按聚类族分组          ← 相近的指标聚在一起
族内：按周期从短到长排列     ← 使"波沿 Z 传播"具有物理意义
```

```
Z轴:  ┌─族A─────────┐┌─族B──────────┐┌─族C────┐
      RSI6 RSI12 RSI24 MA5 MA20 MA60  Vol5 Vol20 ...
      短────────→长   短─────────→长  短──────→长
```

| 需求 | 两级排序 |
|---|---|
| 把相近的曲线移在一起 | ✅ 主序按族 |
| 看"波沿 Z 传播" | ✅ 族内按周期，传播 = 短→长传导 |
| 不泄漏标签 | ✅ 聚类与周期都不用标签 |
| 可复现 | ✅ 全自动 |

### 全部排序方案对比

| 排序依据 | 是否泄漏 | 是否有意义 | 建议 |
|---|---|---|---|
| 与转折日的贴合度 | ❌ **泄漏** | 看似很强 | 仅训练期算 + 冻结，当**检验**用 |
| 波动率大小 | ✅ 无 | ⚠️ 同义反复 | ❌ 不推荐 |
| 相关性聚类（最优叶序） | ✅ 无 | ✅ 同族相邻 | ⭐ 主推 |
| 周期长短 | ✅ 无 | ✅ 传播有物理意义 | ⭐ 主推 |
| **两级：族 + 族内周期** | ✅ 无 | ✅✅ | ⭐⭐ **最佳** |

## 10. 补充（v1.1）：用户的三点反驳与精确回应

> 用户提出三点：① 归一化只是把不同量纲统一到 [0,1]，指标本身无未来函数，
> 为何算泄漏；② 补充说明：先用 sklearn 等生成 1000 多个指标，
> 再用 LightGBM 排序选出最有相关性的 150 个；
> ③ "我就是要用实际股票波动和指标波动对比，越贴合越证明该指标适合我的需求，
> 这不存在什么问题啊？"

### 10.1 归一化：术语没错，泄漏在「缩放」这一步

**术语确认**：把不同量纲统一到 [0,1] 确实叫**归一化**（精确说是 **Min-Max 缩放**）。用词无误。

**关键区分：这是两个独立步骤**

```
第 1 步：算指标      MA20 = 过去 20 天均值        ← ✅ 因果，无问题
第 2 步：缩放到[0,1]  (x - min) / (max - min)     ← ❓ min/max 来自哪段数据？
```

> **第 1 步没有未来函数 ≠ 第 2 步没有未来函数。泄漏在第 2 步。**

**具体数字例子**

| 时间 | 事件 |
|---|---|
| 2010 年某天 | RSI = 70，**当时的历史最高** |
| 2015 年某天 | RSI = 95，创新高 |

看 **2010 年那天**的归一化值：

| 缩放范围 | 2010 年那天的结果 | 含义 |
|---|---|---|
| **全历史 min-max** | 70 / 95 = **0.74** | "中等偏高" |
| 只用截至 2010 的数据 | 70 / 70 = **1.00** | "**历史极值！**" |

> 同一天、同一个指标值，归一化结果完全不同。
> 差别来自**2015 年才发生的那个 95** —— 2010 年当天不可能知道。

**⭐ 该泄漏恰好抹平了要找的信号**

> 全历史 min-max 会**系统性压缩早期数据的极端程度**：
> 2010 年那天本是"历史极值"(1.00)，被后来的 95 压成"中等偏高"(0.74)。
>
> 而本项目要找的正是"**转折点时指标有多极端**"。
> → **这个泄漏正好把要找的信号抹平了。**

另：Min-Max **对异常值极度敏感** —— 一次极端值会把其余年份全部压进很窄区间，图上一片平淡。

### 10.2 ⭐⭐ 建模阶段根本不需要归一化（最简解法）

> **LightGBM（及所有树模型）完全不受量纲影响** ——
> 树只判断"该特征 > 某阈值吗"，乘或除以 1000 结果完全相同。

| 用途 | 需要归一化 | 做法 |
|---|---|---|
| **LightGBM 建模** | ❌ **完全不需要** | 直接用原始指标 → **泄漏自动消失** |
| **可视化**（映射颜色/气泡大小） | ✅ 必须有界 | `x.rolling(250).rank(pct=True)` |
| 跨指标数值比较 | ✅ | 同上 |
| 线性模型 / 神经网络 | ✅ | 同上 |

> **结论：建模时干脆删掉归一化这一步，泄漏问题直接消失。**
> 比"修归一化"更简单 —— 是"删掉它"。

### 10.3 1000+ → 150 的筛选：这是更严重的泄漏

用户补充确认：用 1000 多个指标 + LightGBM 排序选出 150 个。

#### 问题 1：多重比较

**假设那 1000 多个指标全是纯噪音，毫无预测力。** 按统计规律，5% 显著性水平下：

> **1000 × 5% ≈ 50 个指标会"看起来显著" —— 纯粹靠运气。**

而从 1000 多个里选了 150 个（约 15%）。
→ **这 150 个里，有多少是真信号，多少是这 50 个运气选手？**
候选池越大，问题越严重；1000 个候选**必然**产出一批"历史上碰巧很准"的指标。

#### 问题 2：LightGBM 特征重要性在共线特征上极不稳定

1000 多个指标全部派生自同一份 OHLCV → **必然大量共线**。

| 现象 | 说明 |
|---|---|
| 同族指标**互相抢功劳** | RSI-12 与 RSI-14 几乎相同，LightGBM 会随机偏爱其一 |
| **换 `random_state` 排名就变** | 判断重要性是否可靠的最简单测试 |
| 重要性 ≠ 预测力 | gain/split 高只说明"树喜欢用它分裂" |

**更稳健的替代**：permutation importance、多 seed 平均排名、分组（族级）重要性。

#### 两个立即可做的检验

- **检验 A（换 seed）**：用 3 个不同 `random_state` 重跑排序，看前 150 名重合度。
  若仅 60–70%，说明排名很大程度是随机的。
- **检验 B（前后期稳定性）**：2006–2015 选一次、2016–2025 再选一次，看排名是否一致。

### 10.4 ⭐ 关于「贴合度」：用户说得对，前述表述需修正

#### 先承认

**"衡量指标与目标的贴合度"完全正当，而且必须做** —— 这就是特征选择，
是所有机器学习的标准步骤。**此前表述让用户以为在否定这件事，是表述不清。**

#### 真正的问题所在

**问题不在"衡量贴合度"，而在"用同一份数据既做选择、又做验证"。**

| 动作 | 用什么数据 | 可以看答案吗 |
|---|---|---|
| **① 选择**（找出哪些指标贴合） | 训练期 | ✅ **可以，必须看** |
| **② 验证**（证明这套方法有效） | **没参与过①的数据** | ❌ **不可以** |

> **用户在 ① 上完全正确。问题只在于没有留出 ② 用的数据。**

#### 类比

> **可以先看着答案研究一道题，总结出解题思路** —— 完全合理，这是学习。
> **但不能拿同一道题来证明"我已掌握这个知识点"** —— 因为见过答案。
> 要证明掌握，得做一道**没见过的新题**。

当前状况：看着 20 年的答案总结出 150 个指标，**但没留下任何"新题"来考自己。**

#### 为何对本项目尤其关键

> 最终目标是**在明天开盘前判断今天是不是转折点**。明天是**从未见过的数据**。
> 因此必须回答："这套在历史上贴合的指标，在**没见过的数据**上还贴合吗？"
>
> **历史上贴合 ≠ 未来贴合。** 而这个问题只能用"没参与筛选的数据"来回答。

#### 正确的三段划分

```
2006–2015   选指标、算贴合度、定 Z 轴排序      ← 允许充分看答案
2016–2021   调参数、试阈值                     ← 少量使用
2022–2025   完全冻结，全部做完后只看一次       ← 检验
```

#### ⭐ 换个角度：这不是限制，而是给成果发证书

> **若那 150 个指标真捕捉到了稳定规律，则用 2006–2015 选出的那批，
> 在 2022–2025 上应仍然有效。**
>
> **这个检验不会毁掉成果 —— 它会证明成果。**

反之：若通不过，说明该成果本就不存在，只是历史巧合。
**而这件事早知道远好过晚知道 —— 晚知道的代价是真金白银。**

→ 不应把该检验视为障碍，而应主动去做：
它是唯一能拿到的"这套方法真的有用"的证据。

## 11. 补充（v1.2）：归一化只用于可视化 —— 撤回一条结论，但发现更实际的问题

> 用户澄清：归一化**从未用于 LightGBM**，只用于河流图和 3D 比较图，
> 目的是"防止各指标叠加在一起薄厚不均，有的甚至差几十倍"。

### 11.1 撤回一条结论

| 此前说法 | 修正 |
|---|---|
| "全历史归一化导致建模泄漏" | ❌ **不成立**。喂给 LightGBM 的是原始指标值，未经缩放 |
| "建议建模时删掉归一化" | ✅ 用户本来就没用 —— 该建议对其多余 |

> **用户在这一点上的做法是正确的。**

### 11.2 但仍剩一个问题：图要用于「当下判断」

用户目标明确包含："开盘前五分钟内、或收盘前两分钟内，判断某支股票是否已到达下跌转折点。"
→ **这些图不只是回顾工具，而是要用于实时判断。**

**关键问题：实盘当天画图，用什么范围缩放？**
只能用**截至当天**的 min/max（明天的极值不可知）。
但过去看的历史图用的是**全 20 年**的 min/max。
> **两张图不是同一个尺度。**

#### 具体后果

假设眼睛从历史图学到"转折日某族条带会鼓到 0.75 左右"：

| 情况 | 后果 |
|---|---|
| 今天某指标创历史新高 | 实盘图显示 **1.00**，超出全部经验范围 |
| 今天某指标数值与 2010 年那天相同 | 历史图显示 0.74，实盘图显示 **1.00** —— 同一数值，两个厚度 |

> **同一个原始指标值，在不同时点画出的图上厚度与颜色完全不同**
> → "看到什么图案 → 得出什么结论"这个映射**不稳定**。

这正是**第 0 号铁律：训练-推理一致性** —— 只不过这次被训练的是**眼睛**而非模型。

> 若图纯用于事后理解现象、不用于当下判断，则全历史 min-max 影响不大。
> 但用户明确要用它做当下判断，故该问题仍然成立。

### 11.3 ⭐ 更实际的问题：Min-Max 达不到用户的目的

用户用归一化的目的是**消除"薄厚不均，有的差几十倍"**。
**但全历史 Min-Max 恰恰做不到，而且会制造新的薄厚不均。**

#### 两个真实例子

**指标 A：成交量比**（当日量 / 20 日均量）
- 平时 0.5 ~ 2，偶尔暴增到 20（放天量那天）
- 全历史 min-max：`(x - 0.3) / (20 - 0.3)`
- 平时值 1.0 → 缩放后 = **0.036**
- → **95% 的日子挤在 0.03 ~ 0.1 之间，条带薄如纸**

**指标 B：RSI**
- 本身有界 0 ~ 100，实际多分布在 20 ~ 80
- 全历史 min-max → **0.2 ~ 0.8**
- → **条带铺满大半，又厚又明显**

| 指标 | min-max 后实际动态范围 | 条带厚度 |
|---|---|---|
| 成交量比 | 0.03 ~ 0.10 | **极薄** |
| RSI | 0.20 ~ 0.80 | **很厚** |

> **两者厚度差近 10 倍 —— 正是用户想消除的问题。
> Min-Max 把它保留了下来，只是换了个数量级。**

**根本原因**：Min-Max 只对齐"最大最小值"，不对齐"实际分布"。
有长尾的指标，尾巴会把整个正常区间压到角落。

### 11.4 ⭐⭐ 百分位排名才真正实现该目的

```python
pct = x.rolling(250).rank(pct=True)
```

> **百分位排名的结果天生均匀分布在 [0,1]。**
> 这是排名变换的数学性质：N 个值的排名必然是 1,2,…,N，除以 N 即均匀铺满 [0,1]。

| 指标 | 百分位后动态范围 | 条带厚度 |
|---|---|---|
| 成交量比 | **0 ~ 1 均匀** | 正常 |
| RSI | **0 ~ 1 均匀** | 正常 |
| 任何指标 | **0 ~ 1 均匀** | **完全一致** |

> **每个指标的条带动态范围完全相同 —— 这才是真正的"薄厚均匀"。**

#### 换成百分位排名的真正理由

**不是"防泄漏"，而是它更好地实现了用户本来的目的。**

| | Min-Max | **百分位排名** |
|---|---|---|
| 厚度是否均匀可比 | ❌ 差十倍 | ✅ **完全一致** |
| 对异常值 | ❌ 极敏感，一个尖峰毁全图 | ✅ 免疫 |
| 语义 | "在历史最大最小之间的位置" | ✅ "处于过去一年的 X% 分位" |
| 训练-推理一致 | ❌ 尺度会变 | ✅ 滚动窗口天然一致 |

**防泄漏只是顺带的好处。**

### 11.5 河流图的具体实现建议

配合第 8.4 节的**双向堆叠**方案：

```python
pct = x.rolling(250).rank(pct=True)   # 0 ~ 1，均匀分布
dev = pct - 0.5                       # -0.5 ~ +0.5
```

- `dev > 0` → 指标处于历史偏高位 → **向上堆（红）**
- `dev < 0` → 处于历史偏低位 → **向下堆（蓝）**
- 零线固定，厚度均匀

> **厚度均匀 + 方向天然分离 + 零线固定 + 无泄漏 —— 四个需求一次满足。**

### 11.6 结论

| 问题 | 结论 |
|---|---|
| 归一化会影响 LightGBM 吗 | ❌ **不会（用户说得对）** |
| 全历史 min-max 用于**事后回顾** | 🟡 影响不大，但会误判早期的极端程度 |
| 全历史 min-max 用于**当下判断** | ❌ 不行，实盘图与历史图不同尺度 |
| **min-max 能解决"薄厚不均"吗** | ❌ **不能，这是它最大的问题** |
| 该换成什么 | ✅ **`rolling(250).rank(pct=True)`** |

> **一句话：换归一化方式，主要不是为了防泄漏，
> 而是因为所选工具达不到用户自己设定的目的。**

## 2026-07-24 · v1.0 · 路线确立

**讨论主题**：如何学习 AI；如何用表格数据预测趋势并判断转折点。

**确认的前提**
- 个人情况：55 岁、C#/SQL Server 企业开发背景、Python 入门、数学已遗忘、每天最多 2 小时
- 定位：**应用开发**，不做算法研究

**确定的目标**
- 主目标：表格化数据的趋势预测
- 更重要的目标：**判断当下是否为趋势的转折点**（change point / regime shift detection）

**确定的技术栈**
- Pandas（时序 `shift` / `rolling` / `diff`）
- LightGBM 为主力模型
- `TimeSeriesSplit` / walk-forward 验证
- 特征工程为重心
- SHAP 做解释，ruptures 做转折点检测，Optuna 做调参

**明确排除**
- 深度学习（CNN/RNN/LSTM/Transformer）、数学推导、LLM 微调、NLP/图像/语音、ARIMA 数学理论
- 理由：表格与中小规模时序场景下 LightGBM 通常更优；在 2h/天的预算下这些内容性价比过低

**形成的关键认知**
1. 转折点只有事后可确认 → 必须在**及时性与准确性之间权衡**
2. 转折信号藏在**二阶变化**里（涨得越来越慢），而非原始值
3. 时间序列六大陷阱：数据泄漏、随机划分、缺基线、调参假好、确认延迟、概念漂移
4. 期望管理：60% 精确率 + 提前 2~3 期即有价值；号称 90% 准的基本是泄漏
5. 模型定位为**报警器 / 辅助信号**，与个人业务经验结合，而非全自动决策

**产出**
- 六个月学习计划（Pandas 3 周 → ML 概念 3 周 → LightGBM 4 周 → 特征工程 6 周 → 转折点检测 4 周 → 验证落地 6 周）
- 本仓库初始化，路线图与讨论记录归档

**待确认（阻塞方案精细化）**
- 数据领域、时间粒度、历史记录条数、单/多序列、可接受延迟期数

**下一步候选**：A 代码框架（推荐） / B 转折点检测示例 / C 每周任务清单 / D Pandas 时序速成

## 2026-07-24 · v1.1 · 应用场景确定为 A 股，方案大幅修订

**讨论主题**：明确应用场景 —— 中国 A 股日 K 线，盘中判断当日是否为上涨/下跌转折点，可用近 20 年数据。

**新增文档**：[A股转折点检测方案.md](A股转折点检测方案.md)

### 识别出的三个关键矛盾（本次最重要产出）

**1. 日 K 线无法支撑真正的"盘中"判断 —— 致命矛盾**
盘中（如 14:00）并不知道今日收盘价、全天最高/最低、全天成交量。
一旦特征用到这些，即构成未来函数，回测惊艳、实盘归零。
- → 拆为两个方案：**方案 1**（今日开盘前决策，仅用 t-1 及之前完整日 K 线）
  **方案 2**（需分钟级数据，构造当日部分 bar，真正盘中）
- → 决定：先完成方案 1 打好地基（代码可 90% 复用），再升级方案 2

**2. 数据量远小于直觉**
20 年单一指数仅 ≈ 4,850 行；若转折点占 3%，正样本仅约 145 个。
A 股同涨同跌，横截面相关性极高，多股票的行数虚高、有效独立样本远少于行数。
- → 起步用**指数**（沪深300）而非个股；交叉验证必须按时间分组

**3. 20 年跨度内制度剧变，早期规律可能失效**
股权分置改革、2010 股指期货、2015 杠杆牛与股灾、2016 熔断、
2019 科创板 ±20%、2020 创业板 ±20%、注册制、机构化。
- → 必须留最近 2–3 年为纯样本外；必须做分年度稳定性检验
- → 若模型仅在早期有效、近年失效，视为失败

### 战略调整：优先攻"下跌转折点"

理由：
1. **T+1 制度**下卖出信号可当日执行，买入则锁定至次日、承担隔夜风险
2. 规避损失的确定性收益高于追逐利润
3. 下跌伴随波动率放大，特征更显著、更易被模型捕捉

→ 定位从"预测涨跌"改为"**风险预警**"，更务实、更易出成果。

### 新增识别的 A 股特有陷阱

- **前复权价格是未来函数**（会随未来分红送股变化）→ 必须用后复权或复权因子还原
- 涨跌停时买不进/卖不出 → 信号无法执行，回测须排除
- 往返交易成本约 0.1% 量级 → 必须扣成本评估
- 停牌数据空洞、幸存者偏差、ST 涨跌幅不同、必须用真实交易日历
- 标签使用未来 N 日数据 → 时序验证需 **purge + embargo**，否则标签重叠泄漏

### 修订的成功标准（大幅下调，更贴近金融现实）

- AUC 0.54–0.58 即可用；**> 0.65 优先怀疑泄漏**
- 下跌转折精确率 55–60% 已具实用价值
- 更看重「概率分层单调性」而非 AUC
- 必须扣成本后战胜买入持有；必须近 3 年不衰减

### 路线图调整（v1.0 → v1.1）

- **新增阶段 1（第 4–6 周）**：A 股数据获取与清洗（akshare、后复权、交易日历）
- **新增阶段 7（第 27 周起）**：分钟数据升级，实现真正盘中判断
- 阶段 3 目标由"预测准"改为"**流程无泄漏**"
- 阶段 5 聚焦**下跌**转折方向

### 待确认

标的（单指数 / 多指数面板）、训练起点（20 年 / 近 10 年）、
预测视界 N（3 / 5 / 10 日）、是否提前从 baostock 积累分钟数据。

**下一步**：A —— 搭建数据地基与无泄漏框架（`data.py` / `features.py` / `labels.py` / `validate.py`）

### 用户方案 1：9:25 开盘价代理法

做法：9:25 开盘价确定后决策，将当日 收盘/最高/最低 全部用当日开盘价代替，历史日不变，9:30 以开盘价成交。

**评价：思路正确，且有三个天然优势**
1. 9:25 开盘价确实已知，不构成未来函数
2. **几乎无滑点** —— 算特征用的价格 = 实际成交价（多数策略回测幻觉正死于此，方案 1 天然规避）
3. 契合 T+1 —— 卖出信号可在开盘直接执行

**🚨 发现的致命风险：训练-推理一致性**

原表述"以**每个转折点**的开盘价当作收盘价"存在歧义。若替换**只**施加于转折点样本：
- 转折点日：当日振幅 = 0、实体 = 0
- 非转折点日：振幅 > 0
→ 模型只需判断"今日振幅是否为 0"即可 100% 识别标签，**AUC 接近 1.0，实盘完全无效**。
这是**标签通过特征分布反向泄漏**，比普通未来函数更隐蔽（不涉及任何未来价格）。

**确立铁律**：训练集中每一个样本日，无一例外，都必须以与实盘完全相同的方式构造；
训练特征分布必须与实盘 9:25 时刻一致。
自检三法：① 断言 `O==H==L==C` ② 泄漏探针（单用当日 bar 特征训练，AUC 应≈0.5）③ 分布对比。

### 方案 1 的四项改进

1. **弃用当日 K 线形态特征**（振幅/实体/影线恒为 0，是无信息常量），
   改用：**跳空幅度（今开/昨收−1）**、今开在昨日区间中的位置、今开与各均线关系、波动率标准化跳空
2. **纳入集合竞价成交量** ⭐ —— 9:25 已知却几乎总被忽略的信息源。
   竞价量/近20日均量可度量情绪强度；竞价量突增 + 大幅低开 = 恐慌性抛售
3. **纳入隔夜外部信息**（9:25 前均已知，合法）：美股与 VIX、**富时中国A50期货夜盘**（信息量最高）、
   商品、美元指数与 CNH、国债收益率。港股当日不可用（同时开盘），但恒指期货夜盘可用
4. 标记一字板涨跌停为"不可执行"，回测须排除

### 用户方案 2：约 14:58 全市场扫描

**⭐ 指出一个用户尚未意识到的巨大优势：训练-推理一致性天然成立**

14:58 时当日高/低/量已基本定型、价 ≈ 收盘价 → **历史完整日 K 线 ≈ 该时刻状态**
→ **无需任何人为代理**，可直接用历史日 K 线训练，特征信息完整。

→ **推论：方案 1 的天花板必然低于方案 2**，因为方案 1 丢弃了整个交易日的信息
（振幅、实体、影线、全天量、量价关系）。

**三个约束**
1. **收盘集合竞价**（约 14:57–15:00，不接受撤单）→ 14:57 后无法连续竞价成交；
   14:58 决策只能以收盘价通过集合竞价成交。**建议决策时点改为 14:55。**
   （交易规则以交易所最新公告为准）
2. **T+1**：尾盘买入把隔夜风险最大化、次日跳空无法规避 → 再次印证优先做卖出信号
3. **工程**：历史特征须盘前预计算缓存、批量快照接口、向量化、**超时则宁可不交易**

**问题类型转变**：方案 1 = 单标的择时；方案 2 = **横截面选股排序**
→ 后期可用 LightGBM `lambdarank`，评估改用 IC / RankIC 与分档收益单调性；同日样本必须同折。

### ⚠️ 数据积累的紧迫性

- 日 K 线、分钟线（baostock）**可回补**
- **真实盘中快照无法事后补齐**
→ 结论：**现在就写每日自动下载归档脚本**，先攒数据，不等建模。

### 学习节奏确立

用户当前计算机水平较低，决定先集中学习 Python / Pandas，之后固定时间共同推进项目；
学习期间同步跟踪 AI 前沿，评估可用性。

→ 产出 12 周学习清单（Python 核心 2 周 → **Pandas 4 周为重心** → 可视化与工具 2 周 →
A 股数据实战 4 周），含 C# 到 Python 的对照速查表、Pandas 五大坑、可验收自测项。
→ 建立技术雷达文档与「三问过滤法」：① 适合小样本吗 ② 能处理低信噪比吗 ③ 能解决当前瓶颈吗。

### 技术雷达首批结论

- 🟢 **TabPFN / TabPFN-2.5**：面向小样本表格数据的基础模型（约 1 万样本内），
  与本项目 4,850 行的规格吻合；TabPFN-TS 将时序预测转为表格回归。定位为 LightGBM 的**对照模型**
- 🟢 **AutoGluon**：真正价值是作为「**性能上限探测器**」——若它也只有 AUC 0.55，
  即证明瓶颈在数据与特征而非模型；若高得离谱则应立即排查泄漏
- 🟢 **概率校准（Isotonic / Platt）**：对"报警器"定位而言比 AUC 更重要
- 🟡 **TSFM（Chronos-2 / TimesFM-2.5 / Moirai-2 等）**：稳定期可匹敌经典模型，
  但**急剧冲击期退化**、噪音大时退化，且转折点正是结构突变场景 → 仅作基线
- 🟡 **LLM 编程助手**：对学习加速价值最大，但**不可替代自己的理解**（AI 同样会写出带泄漏的代码）
- 🔴 深度时序模型、强化学习交易、GNN、情绪分析：暂不投入

**核心认知**：本项目瓶颈几乎不可能是"模型不够强"。
修正一个泄漏或增加一个好特征的收益，远大于更换更炫的模型。

**下一步**：用户学习 Python / Pandas；Kiro 持续更新技术雷达；
学习到阶段节点后开始编写数据地基代码。

## 2026-07-24 · v1.3.1 · 明确 NumPy 的学习边界

**讨论主题**：NumPy 需要学吗？

**结论：不作为独立学习阶段**，穿插在 Pandas 阶段（第 3–6 周），总投入半天到 1 天。

理由：Pandas 建在 NumPy 之上，日常使用无需直接面对 NumPy。
把它当成"第三门课"会拖慢进度。

**只需掌握七个用法**：`np.where`（⭐ 三分类标签必用，等价于 SQL 的 `CASE WHEN`）、
`np.nan`、`np.sqrt`、`np.log`、`np.sign`、`np.clip`、`.to_numpy()`。

**明确不学**：多维 ndarray、reshape/transpose/axis、广播机制细节、`np.linalg`、
随机数高级用法、结构化数组、`np.einsum`（服务于图像/深度学习/数值计算，本项目无关）。

**⭐ 但提取出一个真正重要的概念：向量化思维**
- C# 背景者最易犯的错是习惯性写 `for` 循环遍历数据行
- 判据：写 for 循环遍历行时就该停下来问"有没有向量化写法"
- 这不是风格问题而是**硬约束**：方案 2 要在 2 分钟内扫描 5000 只股票，只有向量化做得到

## 2026-07-24 · v1.4 · 已有指标热力图资产的评估与泄漏排查

**讨论主题**：用户披露已自行完成的工作 —— 生成 100+ 种日 K 线指标，
筛选出约 150 个对下跌转折点贡献最大者，归一化后按「横轴日期、纵轴指标」排成条带图，
希望以视觉/CNN 方式判断转折点，并询问该图是否叫「河流图」。

**新增文档**：[指标热力图与图像化方法.md](指标热力图与图像化方法.md)

### 术语纠正

**不是河流图。** 河流图（Streamgraph / ThemeRiver）用**条带厚度**编码数值、基线流动；
用户所需的是**热力图**（颜色编码、每行位置固定）。

对本项目必须用热力图，三个理由：① 河流图存在**基线漂移**，指标数值未变但视觉位置乱跳，
跨指标比较失效；② 人眼判断细带厚度精度远低于颜色，150 条带尤甚；
③ 河流图渲染为像素是非线性变形的数据，热力图是原始矩阵的直接映射，信息保真。

**正确叫法**：特征矩阵 / 时间-特征热力图；信号处理中的同类图为语谱图（spectrogram）；
研究方向名为**时间序列图像化（TS2I）**。
注：GAF / MTF / 递归图均针对**单变量**；本项目 150 变量用 `[通道 × 时间]` 直接排布
**更自然、信息更无损**，无需改用 GAF —— 用户这一步选择正确。

### 🚨 识别出两个高度可疑的泄漏（最高优先级）

**泄漏 1：归一化可能用了全历史范围**
若用全历史 mean/std 或 min-max，则 2010 年的数值含 2025 年极值信息 → 未来函数。
必须改为滚动/扩展窗口。
附带洞察：**全局归一化的图看起来更漂亮整齐，恰恰因为它偷看了未来。**

**泄漏 2：150 个指标可能在全部数据上筛选 —— 更隐蔽**
即**特征选择偏差（feature selection bias）**。可怕之处在于**留出测试集也发现不了**，
因为测试集本身参与了特征选择。
正确做法：筛选放入每折训练集内部；或只用最早一段数据筛选后**永久冻结**。
**立即可做的检验**：用 2010–18 与 2019–25 各选一次特征排名，
若"最重要指标"差别很大 → 筛选结果基本是噪音。

### 新识别的技术问题：150 指标高度共线

全部派生自同一份 OHLCV，真实独立维度可能仅 10–20 个。
后果：同族指标互相抢功劳，特征重要性排名极不稳定 → "选出贡献最大的 N 个"本身不可靠。
应对：相关性层次聚类降为 20–30 族。
**顺带解决可视化问题**：热力图行序必须按聚类排列，否则看不出"条带"结构。

### 核心建议：热力图改定位为「诊断仪表盘」而非模型输入

不建议直接上 CNN：4,850 天、约 145 个正样本，即使很小的 CNN 也有上万参数 → 必然背下训练集。
研究印证：Transformer 类在每类样本极少时表现不佳；表格模型在 UCR/UEA 中
约 19% 单变量 / 28% 多变量数据集上能超过 ROCKET 家族。

**改为四轨道对照面板**：热力图（聚类排序）+ 价格 + 真实转折点 + 模型输出概率
→ 一眼看出模型抓到/漏掉/误报了哪些转折。

**更值得做：SHAP 热力图** ⭐ 同样 `[指标 × 时间]` 布局但颜色 = SHAP 值
→ 直接看到模型何时依赖哪些指标，信息量远超静态重要性排名。

> 结论：**人眼的正确用途是"审查模型判断"，而非"替代模型判断"。**

### ⚠️ 风险提示：「看起来挺有用」是危险信号

人眼极善于在噪音中发现模式（apophenia）。能在历史图上看出征兆，
很可能因为**已经知道那里是转折点** —— 后见之明，非预测能力。

**提出盲测方案**（现阶段性价比最高）：随机挑 50 个时间点，
每次只显示截止当日的热力图、遮住后续走势，判断是否为下跌转折，全部完成后统计准确率。
显著高于随机 → 视觉方法确有信息；不显著 → 及时止损。
不需任何机器学习即可验证，且本身是很好的 Matplotlib 练习。

### 新增技术雷达条目：ROCKET / MiniRocket / MultiRocket 🟢

若确实要用卷积/形状思想，应用 ROCKET 家族而非 CNN：随机卷积核 + 线性分类器，
仅需训练线性层，快几个数量级，小样本稳健性好得多。
⚠️ **但其性能随通道数极多而下降 —— 本项目 150 通道正落在此弱点上**
→ 必须先聚类降到 20–30 族。

### 已有资产评估（需要修的是流程，不是思路）

| 资产 | 评价 | 处理 |
|---|---|---|
| 100+ 指标生成逻辑 | ⭐ 最有价值 | 保留 |
| `[指标 × 时间]` 矩阵组织 | ⭐ 方向正确 | 保留 |
| 视觉化审查思路 | ⭐ 正确但需改定位 | 改为诊断工具 |
| 150 指标筛选结果 | ⚠️ 可能不可靠 | 待泄漏排查与稳定性检验 |
| 归一化处理 | ⚠️ 可能泄漏 | 改为滚动窗口 |

**下一步**：立刻排查两个泄漏；学完 Pandas 后做相关性聚类；
第 7–8 周做盲测与四轨道面板。

## 2026-07-24 · v1.5 · 双通道编码与「气泡块」直觉的量化（重要）

**讨论主题**：用户澄清并非真要喂 CNN，而是**借用 CNN 的原理**；
计划用「颜色 + 大小」双通道编码，把相关指标排在一起，观察"一族气泡同时鼓起变红、
另一族缩小变蓝"；河流图同理看组合力。路线为**先人眼验证假设，成立后再自动化**。

**文档更新**：[指标热力图与图像化方法.md](指标热力图与图像化方法.md) 升级至 v1.1，新增第 8 节。

### 修正上一轮的结论

上一轮对河流图"基线漂移"的批评**只在需要比较单个指标时成立**。
用户的用法是"把趋势相近的指标排在一起看一族的总厚度变化" →
**堆叠恰恰是优点**，族内累加的总厚度正是要看的合力。
→ **修正：河流图对"看组合力"是合适的**，但应改为双向堆叠形态。

### 肯定用户的核心直觉

"考虑 CNN 的原理"这一判断很准：**CNN 第一层本质就是检测局部共激活**。
而用领域知识**手工分组 = 人工设计卷积核**。
关键优势：人工设计的核**不需要数据去学**，在仅约 145 个正样本条件下
**比随机初始化的 CNN 更有效、更省数据** —— 实际上绕过了 CNN 最大的短板。

### ⭐ 本轮最大产出：把「看气泡」的直觉量化为可计算特征

设第 t 日第 g 族的因果 z-score 为 z（按方向统一，正=看涨）：

| 眼睛看到的 | 数学表达 | 含义 |
|---|---|---|
| 气泡大小与颜色 | `S = mean(z)` | 族强度 |
| 气泡整齐程度 | `C = abs(mean(sign(z)))` | 族一致性 |
| 气泡参差不齐 | `D = std(z)` | 族内分歧 |
| 红族 vs 蓝族对抗 | `S_看涨 − S_看跌` | 跨族分化 |
| **气泡鼓到最大后开始瘪** | `ΔC = C(t) − C(t−5)` | ⭐ **一致性的二阶变化** |

**最后一项与项目核心洞察完全一致**（转折信号藏在二阶变化里），
是该洞察在**多指标一致性维度**上的版本：

```
转折点假设 = 一致性 C 处于历史高分位 且 ΔC 开始转负
```

→ **视觉直觉由此变为可直接输入 LightGBM 的特征。** 规模约 20–30 族 × 4 统计量 = 80–120 特征，
比 150 个原始指标更有结构、更稳定、共线性更低。

### 新增认知：用户直觉有金融理论支撑

对应概念：**Breadth（广度）、Dispersion（离散度）、Divergence（背离）**。
被广泛观察到的现象：**趋势中段指标高度一致，趋势末端开始出现分歧** ——
即"一致性本身的变化"就是转折信号。
→ 这不是凭空想象的视觉模式，而是在捕捉**真实存在的结构现象**。本方向评价上调。

### 可视化方案定稿：两张图互补

**图 A 气泡矩阵（看结构）**：大小 = `abs(z)` 强度，颜色 = 方向（红涨蓝跌）。
两个通道必须编码**不同的量**，否则冗余。
⚠️ 密度问题：150 × 60 天 = 9000 个气泡，眼睛看不过来 → 必须先降到 20–30 族。

**图 B 双向堆叠河流图（看合力）** ⭐ 关键改进：看涨族向上堆、看跌族向下堆、零线固定。
→ "一部分扩大一部分缩小"变成**上下面积的直接对抗**，转折表现为面积交叉/反转；
且**零线固定，无基线漂移**。保留河流图优点、消除其缺陷。

### 排序必须自动化

**禁止手工"把趋势相近的层调在一起"**：① 会不自觉按已知答案排 → 后见之明；
② 无法复现、无法在新数据上重做。
→ 用 `scipy.cluster.hierarchy` 相关性层次聚类自动排序，可复现且可在训练集内独立完成。
⚠️ 相关性矩阵也必须用训练期数据计算。

### 人眼阶段的定位

| 阶段 | 人眼可行性 |
|---|---|
| 验证假设（有无信号） | ✅ 必须靠人眼 |
| 发现特征（什么模式有预示性） | ✅ 可以 |
| 每天判断 5000 只、2 分钟内 | ❌ 绝对不行 |

→ **人眼负责发现与确认规律，机器负责规模化执行**；8.3 节的量化指标是两者之间的桥梁。

### 方法论肯定

**"先人眼验证假设，成立后再自动化"是正确且专业的做法**，
业界称 **human-in-the-loop 特征发现**，优于"一上来堆 200 个特征调参到 AUC 好看"的常见做法。
→ **顺序应保持：先理解现象 → 再量化 → 再自动化。**

**下一步**：排查两处泄漏 → 层次聚类降维 → 第 7–8 周画两张图并做盲测 →
计算 S/C/D/ΔC 交给 LightGBM。

## 2026-07-24 · v1.6 · 3D 设想评估：救回「周期维度」这块金子（重要）

**讨论主题**：用户提到最早曾设想用 C# + 3D 把 150 个指标放在一个空间里排开，
从不同角度观察条带；后因「3D 难用计算机提取规则」「可简化成河流图」而放弃，询问判断是否正确。

**文档更新**：[指标热力图与图像化方法.md](指标热力图与图像化方法.md) 升级至 v1.2，新增第 10 节。

### 结论：放弃正确，但第二个理由需修正

- ✅ 理由①「3D 难提取规则」**完全正确**，还可补充三条硬性原因：
  **遮挡（occlusion）**、**透视失真导致无法定量比较**、**深度感知精度远低于平面位置与颜色**，
  以及**必须旋转才能理解 → 不可复现、无法截图沉淀、无法批量扫描**
  （最后一条对"收盘前 2 分钟扫 5000 只"的目标尤其致命）
- ⚠️ 理由②「可简化成河流图」**需修正**：这一说法暗示有信息损失，但实情是
  数据结构 `[150 指标 × N 天]` **本质二维**，3D 的第三轴（高度=数值）
  只是把"颜色/大小"换成了"高度" → **3D 并未增加信息维度，只增加视觉负担**
  → 准确说法：**3D 从一开始就没有比 2D 多装任何东西；没有损失，只是甩掉了包袱**
  → 这也解释了换成热力图后"够用"的感觉：**不是妥协，是回到了正确的表示**

### ⭐⭐ 本轮最大产出：被一起扔掉的「周期维度」应救回来

"想要第三个维度"的冲动是对的，只是**轴选错了**。

若 150 个指标中含大量"同一指标的不同周期"（RSI-6/12/24、MA偏离-5/10/20/60、
波动率-5/20/60…），则数据的**真实结构本就是三维**：

```
[指标类型 × 周期参数 × 时间]    ← 天然的三维
```

> **真正想要的第三维不是"数值高度"，而是"时间尺度"。**
> 该维度**真实存在且独立**。当年的直觉抓到了东西，只是没找对轴。

### 周期维度对转折点判断的价值（新增认知）

| 现象 | 含义 |
|---|---|
| **短周期已转，长周期未转** | ⭐ **早期转折信号（最有价值）** |
| 全周期同时转向 | 强烈确认但很可能**已经晚了** |
| 短周期反复摇摆、长周期稳定 | 噪音，非转折 |
| 长周期先转、短周期跟随 | 罕见，通常是数据问题 |

术语：**信号的期限结构（term structure）/ 多尺度一致性**。

**可量化并与 v1.5 的假设合并**：

| 量 | 公式 |
|---|---|
| 尺度分化 | `S_短 − S_长` |
| 传导时滞 | 短周期转向后几天长周期跟上 |
| 短周期领先度 | `C_短 − C_长` |

```
早期下跌转折信号 =
    短周期族一致性 已转负
  且 长周期族一致性 仍为正但 ΔC < 0     ← 长周期开始松动
  且 尺度分化 处于历史极端分位
```

即"**短周期先塌，长周期开始跟着松**"，正对应视觉上"气泡从一头开始瘪"。

### 可视化方案：小倍数图，不是 3D

按周期分面并排三张 2D 气泡矩阵（短/中/长周期）。
相比 3D 立体图：无遮挡、可定量比较、可截图沉淀、可批量生成，
且**"短周期先转"一眼看出**（3D 要旋转半天）。

> 通用经验：**想加第三个维度时，答案通常是"多画几张 2D 图"，而不是"画一张 3D 图"。**

### 关于用 C# 做可视化

技术可行（WPF / Unity / OpenTK）但不建议。
探索试错用 **Python**（Matplotlib 生态成熟、几行出图）；
最终生产系统与现有系统对接用 **C#**（用户强项）。
与既定路线一致：Python 研究 → API → C# 调用。
理由：探索阶段用 C# 画图会有 80% 时间耗在画图代码上，Python 里比例相反。

### 「从不同角度观察」的正确满足方式

**交互式 2D + 时间滑块**、**动画**（用时间作第四维而非挤进空间轴）。
工具：Matplotlib animation、Plotly、Streamlit 滑块。

**下一步补充**：清点 150 个指标中哪些是"同族不同周期"，
重组为 `[指标类型 × 周期 × 时间]`；后续画按周期分面的小倍数图；
计算尺度分化、传导时滞、短周期领先度作为特征。

## 2026-07-24 · v1.7 · 3D 设想的准确形态：曲面图/瀑布图，与山脊图替代方案

**讨论主题**：用户澄清 3D 设计的准确形态 —— X = 时间（一日一格）、
**Y = 指标数值（高度，归一化）**、Z = 150 个指标依次排列；
目的是看波动切面，以及"Z 轴上不同指标的 y 值从远到近/从近到远来回波动"。

**文档更新**：[指标热力图与图像化方法.md](指标热力图与图像化方法.md) 升级至 v1.3，新增第 11 节
（**修正第 10 节部分论断**）。

### 正名与先例

该设计的正式名称：**3D 曲面图（surface plot）/ 瀑布图（waterfall plot）**，
后者是**信号处理与振动分析的经典图形**。其 2D 版本为**山脊图（ridgeline / joyplot）**。

⭐ **有力先例**：振动分析与声学领域走过完全相同的路 —— 早年普遍用 3D 瀑布图，
但**现在自动化分析几乎全部改用 2D 彩色谱图，3D 只留作演示与讲解**，
原因与用户自己发现的完全一致。
→ **用户的判断不是外行直觉，而是已被其他工程领域验证过的结论。**

### 修正第 10.3 节的论断

上一轮称"3D 没有增加任何东西"**过于绝对**。准确说法：

| | 数值编码通道 | 读取精度 |
|---|---|---|
| 热力图 | 颜色 | 低 |
| 3D 曲面 | **高度** | **高**（人眼读高度最准） |

信息量相同，但**"高度"通道比"颜色"读得更准** —— 单条曲线时 3D 确实更清楚。

**但 150 条曲线的遮挡会完全抵消该优势**，且**遮挡随视角变化**
（某角度看到"山峰鼓起"，旋转 30° 可能发现是前排挡出的假象）。
→ 原判断成立，但原因是"信息被遮挡且取决于视角"，而非"没信息"。

### ⚠️ 识别出一个可能的同义反复

用户观察"下跌转折日时波动大的靠近 Z 轴零轴、波动小的离零很远"。
**若 Z 轴当时按波动率排序，则该现象由排序方式决定，不是数据规律** —— 同义反复。

> 这类错误极常见：**看到的"规律"其实是自己排列方式的倒影。**

**判别方法（10 分钟）**：把 Z 轴改为随机顺序重画。
现象消失 → 来自排序；仍能看到"某群指标在转折日集中动" → 才是真信号。

### ⭐⭐ 「波沿 Z 轴传播」是本轮金子

用户观察"Z 轴上不同指标的 y 值从远到近/从近到远来回波动"，
其意义**完全取决于 Z 轴排序方式**：

| Z 轴排序 | 含义 |
|---|---|
| 随机 | ❌ 无意义 |
| 按波动率 | ⚠️ 同义反复 |
| 按相关性聚类 | 🟡 有一定意义 |
| **按周期长短（短→长）** | ⭐⭐ **有明确物理意义** |

按周期排序后："波从近到远传播" = **信号从短周期向长周期传导**，
即上一轮的**传导时滞 / 信号期限结构**。
而"**波刚从短周期开始往长周期推**"的瞬间即**早期转折信号**。

→ **用户的两个想法（3D 波传播 + 气泡鼓瘪）指向同一个结构，是好迹象。**

**可量化（不必画 3D）**：相邻 Z 层的**互相关最优时滞**（传播速度）、
**时滞符号**（传播方向：短→长正常，长→短异常）、**互相关峰值**（传播强度）。
三者可直接作为 LightGBM 特征。

## 2026-07-24 · v1.8 · 泄漏排查结果确认与 Z 轴排序方法（重要）

**讨论主题**：用户回答三项排查问题；并提出核心疑问 ——
"怎么把相近的曲线移在一起？如何判断两个指标曲线的相似度和差异度？"
并设想"Z 轴越靠近零，指标与下跌转折日的贴合度越高"。

**新增文档**：[泄漏排查与Z轴排序.md](泄漏排查与Z轴排序.md)

### 排查结论

| 排查项 | 答复 | 判定 |
|---|---|---|
| 归一化范围 | **全历史** | ❌ **确认泄漏** |
| 指标**计算**方式 | MA20 = 过去 20 天 | ✅ **正确、因果、无问题** |
| 指标**筛选**所用数据 | ⚠️ 答复的是计算方式而非筛选范围 | ⏳ **待确认** |
| Z 轴排序 | 尚未研究，拟按"与转折日贴合度"排 | ❌ **该方案会泄漏标签** |

### 归一化修复：推荐滚动百分位排名

三方案：滚动 z-score / 扩展窗口 z-score / **滚动百分位排名 `x.rolling(250).rank(pct=True)`**。

**推荐第三个**，因为：① **天然有界 [0,1]**，映射到颜色与气泡大小必须有界；
② 对异常值免疫（金融厚尾，z-score 遇暴跌可飙至 ±8，把其余日期压成一片灰）；
③ 跨指标可比；④ 语义清晰。

⚠️ **心理准备**：改后图会变得没那么整齐漂亮。**此前的整齐来自偷看未来；丑一点的图才是真实的样子。**

### 澄清一个概念混淆：「指标计算」≠「指标筛选」

用户答的是**计算方式**（MA20 用过去 20 天 → ✅ 完全正确的因果计算），
而问题是**筛选范围**（从 100 多种里挑出 150 个"贡献最大"时用了哪些年份）。

泄漏类比：**考完试后按分数给学生排座位，然后宣布"我发现前排的学生成绩好"。**

另注意数字不一致："生成 100 多种，选出 150 个"（150 > 100）→
推测实为 100 多种类型 × 不同周期 = 几百个再选 150。
**若如此，则印证"150 个中含大量同族不同周期"，周期维度是现成的。**

### ⚠️ Z 轴按「与转折日贴合度」排序会泄漏标签

该排序用到"下跌转折日"标签（未来信息）→
会在 Z=0 附近看到极漂亮的模式，但那是**按答案排出来的**，
**图变成"答案的可视化"而非"数据的可视化"**。
与特征筛选泄漏是同一错误的两种形式：都让"答案"参与了"输入"的构造。

**合法版本（保留想法 + 加纪律）**：只用训练期（2006–2015）算贴合度确定排序 →
**冻结** → 在 2016–2025 上检查是否仍成立。
后期仍成立 → 真规律且证据很强；后期乱了 → 对训练期噪音的过拟合。
**该检验本身极有价值**，直接回答"这套指标有无稳定预测力"。

### ⭐ 回答用户核心疑问：相似度度量与排序方法

**相似度度量（按适用度）**
1. **斯皮尔曼秩相关** ⭐ 首选（金融厚尾，比 Pearson 稳）
2. 皮尔逊相关（易被极端值带偏）
3. **带时滞的互相关** ⭐ 对本项目特别重要 ——
   **传播的本质就是时滞**；两指标可能高度相似但错开 3 天，
   普通相关系数会低估。相似度取最优时滞下的相关系数，并记录时滞（= 传播速度特征）
4. DTW（更强但慢，后期再试）

**排序标准答案：层次聚类 + 最优叶序**
```python
corr = train.corr(method="spearman")      # ⚠️ 只用训练期
dist = 1 - corr.abs()                      # 负相关也是同一信息，取绝对值
Z = linkage(squareform(dist), method="average", optimal_ordering=True)
order = leaves_list(Z)
```
> **`optimal_ordering=True` 正是"把相近的曲线移在一起"的答案** ——
> 在保持聚类结构前提下旋转分支，使相邻叶子距离最小，Z 轴平滑过渡。

其他可选：谱排序（Fiedler 向量）、一维降维（MDS/UMAP）后排序。

### ⭐⭐ 推荐方案：Z 轴两级排序

```
主序：按聚类族分组       ← 相近的指标聚在一起
族内：按周期从短到长     ← 使"波沿 Z 传播"具有物理意义
```

| 排序依据 | 泄漏 | 有意义 | 建议 |
|---|---|---|---|
| 与转折日贴合度 | ❌ | 看似很强 | 仅训练期算+冻结，当检验用 |
| 波动率大小 | ✅ 无 | ⚠️ 同义反复 | ❌ 不推荐 |
| 相关性聚类（最优叶序） | ✅ 无 | ✅ | ⭐ 主推 |
| 周期长短 | ✅ 无 | ✅ | ⭐ 主推 |
| **两级：族 + 族内周期** | ✅ 无 | ✅✅ | ⭐⭐ **最佳** |

### 总体评估

**坏消息**：归一化确认泄漏、筛选可能泄漏、拟用排序也会泄漏 → 视觉结论需用干净流程重做。

**好消息（更重要）**：
1. **最耗时的资产完好** —— 100 多种指标的计算逻辑因果正确，这是最难重建的部分
2. 三个问题都是**流程**而非思路，改动量都很小（3 行 / 10 行 / 调数据范围）

   有些人一辈子没发现，只反复困惑"回测那么准、实盘就是不行"
4. 直觉全部指向对的地方（二阶变化、共激活、周期传导），出问题的全是可查清单的细节

## 2026-07-24 · v1.9 · 回应三点反驳：修正「贴合度」表述，确认筛选泄漏（重要）

**讨论主题**：用户对上一轮提出三点反驳 ——
① 归一化只是把不同量纲统一到 [0,1]，指标本身无未来函数，为何算泄漏；
② 补充：先用 sklearn 等生成 1000 多个指标，再用 LightGBM 排序选出最相关的 150 个；
③ "我就是要用实际股票波动和指标波动对比，越贴合越证明该指标适合我的需求，这不存在什么问题啊？"

**文档更新**：[泄漏排查与Z轴排序.md](泄漏排查与Z轴排序.md) 升级至 v1.1，新增第 10 节。

### ① 归一化：术语没错，泄漏在「缩放」这一步

**确认用户术语正确**（Min-Max 缩放）。但须区分两个独立步骤：
- 第 1 步算指标（MA20 用过去 20 天）→ ✅ 因果
- 第 2 步缩放 `(x-min)/(max-min)` → ❓ **min/max 来自哪段数据**

> **第 1 步无未来函数 ≠ 第 2 步无未来函数。**

**数字例证**：某指标 2010 年 RSI=70（当时历史最高），2015 年冲到 95。
看 2010 年那天：全历史 min-max → 70/95 = **0.74**（"中等偏高"）；
只用截至 2010 的数据 → 70/70 = **1.00**（"历史极值"）。
差别来自 2015 年才发生的 95。

**⭐ 该泄漏恰好抹平要找的信号**：全历史 min-max **系统性压缩早期数据的极端程度**，
而本项目要找的正是"转折点时指标有多极端" → **泄漏把目标信号抹平了**。
另：Min-Max 对异常值极敏感，一次极端值会把其余年份压进很窄区间。

### ⭐⭐ 最简解法：建模阶段根本不需要归一化

**LightGBM 及所有树模型完全不受量纲影响**（只判断"特征 > 阈值"）。
→ 建模时**直接删掉归一化这一步，泄漏自动消失**；
只有可视化（映射颜色/气泡大小，必须有界）才需要，用 `rolling(250).rank(pct=True)`。
> 比"修归一化"更简单 —— 是"删掉它"。

### ② 1000+ → 150 筛选：更严重的泄漏，且新增两个问题

**多重比较问题**：假设 1000 多个指标全是纯噪音，5% 显著性水平下
**约 50 个会"看起来显著"，纯靠运气**。从 1000 多个里选 150 个（15%），
其中有多少是这 50 个运气选手？候选池越大问题越严重。

**LightGBM 重要性在共线特征上极不稳定**：1000+ 指标全派生自同一份 OHLCV，必然大量共线
→ 同族互相抢功劳、**换 random_state 排名就变**、重要性 ≠ 预测力。
更稳健：permutation importance、多 seed 平均排名、族级重要性。

**两个立即可做的检验**：
- 检验 A：换 3 个 seed 重跑，看前 150 名重合度（若仅 60–70% 说明排名很大程度随机）
- 检验 B：2006–15 与 2016–25 各选一次，看排名是否一致

### ③ ⭐ 修正上一轮对「贴合度」的表述（用户说得对）

**先承认**：**"衡量指标与目标的贴合度"完全正当且必须做** —— 这就是特征选择，
是标准 ML 步骤。上一轮表述让用户以为在否定这件事，是表述不清。

**真正的问题**：不在"衡量贴合度"，而在"**用同一份数据既做选择、又做验证**"。

| 动作 | 数据 | 可否看答案 |
|---|---|---|
| ① 选择（找出哪些指标贴合） | 训练期 | ✅ **可以，必须看** |
| ② 验证（证明方法有效） | **未参与①的数据** | ❌ 不可以 |

> **用户在 ① 上完全正确，问题只是没留出 ② 用的数据。**

**类比**：可以看着答案研究一道题、总结解题思路（合理，这是学习）；
但不能拿同一道题证明"我掌握了这个知识点"，要证明得做一道没见过的新题。

**对本项目尤其关键**：最终目标是在明天开盘前判断 —— 明天是从未见过的数据。
**历史上贴合 ≠ 未来贴合**，该问题只能用未参与筛选的数据回答。

**三段划分**：2006–2015 选指标/算贴合度/定排序（允许充分看答案）→

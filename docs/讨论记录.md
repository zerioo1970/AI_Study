## 2026-07-24 · v1.0 · 路线确立

**讨论主题**：如何学习 AI；如何用表格数据预测趋势并判断转折点。

**确认的前提**
- 个人情况：55 岁、C#/SQL Server 企业开发背景、Python 入门、数学已遗忘、每天最多 2 小时
- 定位：**应用开发**，不做算法研究

**确定的目标**
- 主目标：表格化数据的趋势预测
- 更重要的目标：**判断当下是否为趋势的转折点**（change point / regime shift detection）

**确定的技术栈**
- Pandas（时序 `shift` / `rolling` / `diff`）
- LightGBM 为主力模型
- `TimeSeriesSplit` / walk-forward 验证
- 特征工程为重心
- SHAP 做解释，ruptures 做转折点检测，Optuna 做调参

**明确排除**
- 深度学习（CNN/RNN/LSTM/Transformer）、数学推导、LLM 微调、NLP/图像/语音、ARIMA 数学理论
- 理由：表格与中小规模时序场景下 LightGBM 通常更优；在 2h/天的预算下这些内容性价比过低

**形成的关键认知**
1. 转折点只有事后可确认 → 必须在**及时性与准确性之间权衡**
2. 转折信号藏在**二阶变化**里（涨得越来越慢），而非原始值
3. 时间序列六大陷阱：数据泄漏、随机划分、缺基线、调参假好、确认延迟、概念漂移
4. 期望管理：60% 精确率 + 提前 2~3 期即有价值；号称 90% 准的基本是泄漏
5. 模型定位为**报警器 / 辅助信号**，与个人业务经验结合，而非全自动决策

**产出**
- 六个月学习计划（Pandas 3 周 → ML 概念 3 周 → LightGBM 4 周 → 特征工程 6 周 → 转折点检测 4 周 → 验证落地 6 周）
- 本仓库初始化，路线图与讨论记录归档

**待确认（阻塞方案精细化）**
- 数据领域、时间粒度、历史记录条数、单/多序列、可接受延迟期数

**下一步候选**：A 代码框架（推荐） / B 转折点检测示例 / C 每周任务清单 / D Pandas 时序速成

## 2026-07-24 · v1.1 · 应用场景确定为 A 股，方案大幅修订

**讨论主题**：明确应用场景 —— 中国 A 股日 K 线，盘中判断当日是否为上涨/下跌转折点，可用近 20 年数据。

**新增文档**：[A股转折点检测方案.md](A股转折点检测方案.md)

### 识别出的三个关键矛盾（本次最重要产出）

**1. 日 K 线无法支撑真正的"盘中"判断 —— 致命矛盾**
盘中（如 14:00）并不知道今日收盘价、全天最高/最低、全天成交量。
一旦特征用到这些，即构成未来函数，回测惊艳、实盘归零。
- → 拆为两个方案：**方案 1**（今日开盘前决策，仅用 t-1 及之前完整日 K 线）
  **方案 2**（需分钟级数据，构造当日部分 bar，真正盘中）
- → 决定：先完成方案 1 打好地基（代码可 90% 复用），再升级方案 2

**2. 数据量远小于直觉**
20 年单一指数仅 ≈ 4,850 行；若转折点占 3%，正样本仅约 145 个。
A 股同涨同跌，横截面相关性极高，多股票的行数虚高、有效独立样本远少于行数。
- → 起步用**指数**（沪深300）而非个股；交叉验证必须按时间分组

**3. 20 年跨度内制度剧变，早期规律可能失效**
股权分置改革、2010 股指期货、2015 杠杆牛与股灾、2016 熔断、
2019 科创板 ±20%、2020 创业板 ±20%、注册制、机构化。
- → 必须留最近 2–3 年为纯样本外；必须做分年度稳定性检验
- → 若模型仅在早期有效、近年失效，视为失败

### 战略调整：优先攻"下跌转折点"

理由：
1. **T+1 制度**下卖出信号可当日执行，买入则锁定至次日、承担隔夜风险
2. 规避损失的确定性收益高于追逐利润
3. 下跌伴随波动率放大，特征更显著、更易被模型捕捉

→ 定位从"预测涨跌"改为"**风险预警**"，更务实、更易出成果。

### 新增识别的 A 股特有陷阱

- **前复权价格是未来函数**（会随未来分红送股变化）→ 必须用后复权或复权因子还原
- 涨跌停时买不进/卖不出 → 信号无法执行，回测须排除
- 往返交易成本约 0.1% 量级 → 必须扣成本评估
- 停牌数据空洞、幸存者偏差、ST 涨跌幅不同、必须用真实交易日历
- 标签使用未来 N 日数据 → 时序验证需 **purge + embargo**，否则标签重叠泄漏

### 修订的成功标准（大幅下调，更贴近金融现实）

- AUC 0.54–0.58 即可用；**> 0.65 优先怀疑泄漏**
- 下跌转折精确率 55–60% 已具实用价值
- 更看重「概率分层单调性」而非 AUC
- 必须扣成本后战胜买入持有；必须近 3 年不衰减

### 路线图调整（v1.0 → v1.1）

- **新增阶段 1（第 4–6 周）**：A 股数据获取与清洗（akshare、后复权、交易日历）
- **新增阶段 7（第 27 周起）**：分钟数据升级，实现真正盘中判断
- 阶段 3 目标由"预测准"改为"**流程无泄漏**"
- 阶段 5 聚焦**下跌**转折方向

### 待确认

标的（单指数 / 多指数面板）、训练起点（20 年 / 近 10 年）、
预测视界 N（3 / 5 / 10 日）、是否提前从 baostock 积累分钟数据。

**下一步**：A —— 搭建数据地基与无泄漏框架（`data.py` / `features.py` / `labels.py` / `validate.py`）

### 用户方案 1：9:25 开盘价代理法

做法：9:25 开盘价确定后决策，将当日 收盘/最高/最低 全部用当日开盘价代替，历史日不变，9:30 以开盘价成交。

**评价：思路正确，且有三个天然优势**
1. 9:25 开盘价确实已知，不构成未来函数
2. **几乎无滑点** —— 算特征用的价格 = 实际成交价（多数策略回测幻觉正死于此，方案 1 天然规避）
3. 契合 T+1 —— 卖出信号可在开盘直接执行

**🚨 发现的致命风险：训练-推理一致性**

原表述"以**每个转折点**的开盘价当作收盘价"存在歧义。若替换**只**施加于转折点样本：
- 转折点日：当日振幅 = 0、实体 = 0
- 非转折点日：振幅 > 0
→ 模型只需判断"今日振幅是否为 0"即可 100% 识别标签，**AUC 接近 1.0，实盘完全无效**。
这是**标签通过特征分布反向泄漏**，比普通未来函数更隐蔽（不涉及任何未来价格）。

**确立铁律**：训练集中每一个样本日，无一例外，都必须以与实盘完全相同的方式构造；
训练特征分布必须与实盘 9:25 时刻一致。
自检三法：① 断言 `O==H==L==C` ② 泄漏探针（单用当日 bar 特征训练，AUC 应≈0.5）③ 分布对比。

### 方案 1 的四项改进

1. **弃用当日 K 线形态特征**（振幅/实体/影线恒为 0，是无信息常量），
   改用：**跳空幅度（今开/昨收−1）**、今开在昨日区间中的位置、今开与各均线关系、波动率标准化跳空
2. **纳入集合竞价成交量** ⭐ —— 9:25 已知却几乎总被忽略的信息源。
   竞价量/近20日均量可度量情绪强度；竞价量突增 + 大幅低开 = 恐慌性抛售
3. **纳入隔夜外部信息**（9:25 前均已知，合法）：美股与 VIX、**富时中国A50期货夜盘**（信息量最高）、
   商品、美元指数与 CNH、国债收益率。港股当日不可用（同时开盘），但恒指期货夜盘可用
4. 标记一字板涨跌停为"不可执行"，回测须排除

### 用户方案 2：约 14:58 全市场扫描

**⭐ 指出一个用户尚未意识到的巨大优势：训练-推理一致性天然成立**

14:58 时当日高/低/量已基本定型、价 ≈ 收盘价 → **历史完整日 K 线 ≈ 该时刻状态**
→ **无需任何人为代理**，可直接用历史日 K 线训练，特征信息完整。

→ **推论：方案 1 的天花板必然低于方案 2**，因为方案 1 丢弃了整个交易日的信息
（振幅、实体、影线、全天量、量价关系）。

**三个约束**
1. **收盘集合竞价**（约 14:57–15:00，不接受撤单）→ 14:57 后无法连续竞价成交；
   14:58 决策只能以收盘价通过集合竞价成交。**建议决策时点改为 14:55。**
   （交易规则以交易所最新公告为准）
2. **T+1**：尾盘买入把隔夜风险最大化、次日跳空无法规避 → 再次印证优先做卖出信号
3. **工程**：历史特征须盘前预计算缓存、批量快照接口、向量化、**超时则宁可不交易**

**问题类型转变**：方案 1 = 单标的择时；方案 2 = **横截面选股排序**
→ 后期可用 LightGBM `lambdarank`，评估改用 IC / RankIC 与分档收益单调性；同日样本必须同折。

### ⚠️ 数据积累的紧迫性

- 日 K 线、分钟线（baostock）**可回补**
- **真实盘中快照无法事后补齐**
→ 结论：**现在就写每日自动下载归档脚本**，先攒数据，不等建模。

### 学习节奏确立

用户当前计算机水平较低，决定先集中学习 Python / Pandas，之后固定时间共同推进项目；
学习期间同步跟踪 AI 前沿，评估可用性。

→ 产出 12 周学习清单（Python 核心 2 周 → **Pandas 4 周为重心** → 可视化与工具 2 周 →
A 股数据实战 4 周），含 C# 到 Python 的对照速查表、Pandas 五大坑、可验收自测项。
→ 建立技术雷达文档与「三问过滤法」：① 适合小样本吗 ② 能处理低信噪比吗 ③ 能解决当前瓶颈吗。

### 技术雷达首批结论

- 🟢 **TabPFN / TabPFN-2.5**：面向小样本表格数据的基础模型（约 1 万样本内），
  与本项目 4,850 行的规格吻合；TabPFN-TS 将时序预测转为表格回归。定位为 LightGBM 的**对照模型**
- 🟢 **AutoGluon**：真正价值是作为「**性能上限探测器**」——若它也只有 AUC 0.55，
  即证明瓶颈在数据与特征而非模型；若高得离谱则应立即排查泄漏
- 🟢 **概率校准（Isotonic / Platt）**：对"报警器"定位而言比 AUC 更重要
- 🟡 **TSFM（Chronos-2 / TimesFM-2.5 / Moirai-2 等）**：稳定期可匹敌经典模型，
  但**急剧冲击期退化**、噪音大时退化，且转折点正是结构突变场景 → 仅作基线
- 🟡 **LLM 编程助手**：对学习加速价值最大，但**不可替代自己的理解**（AI 同样会写出带泄漏的代码）
- 🔴 深度时序模型、强化学习交易、GNN、情绪分析：暂不投入

**核心认知**：本项目瓶颈几乎不可能是"模型不够强"。
修正一个泄漏或增加一个好特征的收益，远大于更换更炫的模型。

**下一步**：用户学习 Python / Pandas；Kiro 持续更新技术雷达；
学习到阶段节点后开始编写数据地基代码。

## 2026-07-24 · v1.3.1 · 明确 NumPy 的学习边界

**讨论主题**：NumPy 需要学吗？

**结论：不作为独立学习阶段**，穿插在 Pandas 阶段（第 3–6 周），总投入半天到 1 天。

理由：Pandas 建在 NumPy 之上，日常使用无需直接面对 NumPy。
把它当成"第三门课"会拖慢进度。

**只需掌握七个用法**：`np.where`（⭐ 三分类标签必用，等价于 SQL 的 `CASE WHEN`）、
`np.nan`、`np.sqrt`、`np.log`、`np.sign`、`np.clip`、`.to_numpy()`。

**明确不学**：多维 ndarray、reshape/transpose/axis、广播机制细节、`np.linalg`、
随机数高级用法、结构化数组、`np.einsum`（服务于图像/深度学习/数值计算，本项目无关）。

**⭐ 但提取出一个真正重要的概念：向量化思维**
- C# 背景者最易犯的错是习惯性写 `for` 循环遍历数据行
- 判据：写 for 循环遍历行时就该停下来问"有没有向量化写法"
- 这不是风格问题而是**硬约束**：方案 2 要在 2 分钟内扫描 5000 只股票，只有向量化做得到

**产出**：`Python学习清单.md` 新增 3.5 节「关于 NumPy」，含七个用法表、
本项目真实标签代码示例、不学清单、向量化对比示例。

### 术语纠正

**不是河流图。** 河流图（Streamgraph / ThemeRiver）用**条带厚度**编码数值、基线流动；
用户所需的是**热力图**（颜色编码、每行位置固定）。

对本项目必须用热力图，三个理由：① 河流图存在**基线漂移**，指标数值未变但视觉位置乱跳，
跨指标比较失效；② 人眼判断细带厚度精度远低于颜色，150 条带尤甚；
③ 河流图渲染为像素是非线性变形的数据，热力图是原始矩阵的直接映射，信息保真。

**正确叫法**：特征矩阵 / 时间-特征热力图；信号处理中的同类图为语谱图（spectrogram）；
研究方向名为**时间序列图像化（TS2I）**。
注：GAF / MTF / 递归图均针对**单变量**；本项目 150 变量用 `[通道 × 时间]` 直接排布
**更自然、信息更无损**，无需改用 GAF —— 用户这一步选择正确。

### 🚨 识别出两个高度可疑的泄漏（最高优先级）

**泄漏 1：归一化可能用了全历史范围**
若用全历史 mean/std 或 min-max，则 2010 年的数值含 2025 年极值信息 → 未来函数。
必须改为滚动/扩展窗口。
附带洞察：**全局归一化的图看起来更漂亮整齐，恰恰因为它偷看了未来。**

**泄漏 2：150 个指标可能在全部数据上筛选 —— 更隐蔽**
即**特征选择偏差（feature selection bias）**。可怕之处在于**留出测试集也发现不了**，
因为测试集本身参与了特征选择。
正确做法：筛选放入每折训练集内部；或只用最早一段数据筛选后**永久冻结**。
**立即可做的检验**：用 2010–18 与 2019–25 各选一次特征排名，
若"最重要指标"差别很大 → 筛选结果基本是噪音。

### 新识别的技术问题：150 指标高度共线

全部派生自同一份 OHLCV，真实独立维度可能仅 10–20 个。
后果：同族指标互相抢功劳，特征重要性排名极不稳定 → "选出贡献最大的 N 个"本身不可靠。
应对：相关性层次聚类降为 20–30 族。
**顺带解决可视化问题**：热力图行序必须按聚类排列，否则看不出"条带"结构。

### 核心建议：热力图改定位为「诊断仪表盘」而非模型输入

不建议直接上 CNN：4,850 天、约 145 个正样本，即使很小的 CNN 也有上万参数 → 必然背下训练集。
研究印证：Transformer 类在每类样本极少时表现不佳；表格模型在 UCR/UEA 中
约 19% 单变量 / 28% 多变量数据集上能超过 ROCKET 家族。

**改为四轨道对照面板**：热力图（聚类排序）+ 价格 + 真实转折点 + 模型输出概率
→ 一眼看出模型抓到/漏掉/误报了哪些转折。

**更值得做：SHAP 热力图** ⭐ 同样 `[指标 × 时间]` 布局但颜色 = SHAP 值
→ 直接看到模型何时依赖哪些指标，信息量远超静态重要性排名。

> 结论：**人眼的正确用途是"审查模型判断"，而非"替代模型判断"。**

### ⚠️ 风险提示：「看起来挺有用」是危险信号

人眼极善于在噪音中发现模式（apophenia）。能在历史图上看出征兆，
很可能因为**已经知道那里是转折点** —— 后见之明，非预测能力。

**提出盲测方案**（现阶段性价比最高）：随机挑 50 个时间点，
每次只显示截止当日的热力图、遮住后续走势，判断是否为下跌转折，全部完成后统计准确率。
显著高于随机 → 视觉方法确有信息；不显著 → 及时止损。
不需任何机器学习即可验证，且本身是很好的 Matplotlib 练习。

### 新增技术雷达条目：ROCKET / MiniRocket / MultiRocket 🟢

若确实要用卷积/形状思想，应用 ROCKET 家族而非 CNN：随机卷积核 + 线性分类器，
仅需训练线性层，快几个数量级，小样本稳健性好得多。
⚠️ **但其性能随通道数极多而下降 —— 本项目 150 通道正落在此弱点上**
→ 必须先聚类降到 20–30 族。

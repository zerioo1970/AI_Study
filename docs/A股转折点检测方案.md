# A 股日内转折点检测 —— 技术方案

> 目标：基于中国 A 股日 K 线数据（可用近 20 年），在**每日盘中**判断当天是否为上涨/下跌的转折点。
> 关联文档：[AI学习路线图](AI学习路线图.md) · [讨论记录](讨论记录.md)
>
> ⚠️ 本文档为**技术学习与研究**用途，不构成任何投资建议。未经充分样本外验证的模型不得用于实盘。

- 创建日期：2026-07-24
- 版本：v1.0

---

## 1. 必须先承认的三个现实

### 1.1 数据粒度与决策时点不匹配（最关键）

**日 K 线 = 一天一行**，字段为 开/高/低/收/量。
而"盘中判断" = 你在 14:00 就要做决定。此刻你**并不知道**：

- 今日收盘价
- 今日全天最高价 / 最低价
- 今日全天成交量

> 🚨 **只要特征里用到了今日的 收盘价 / 全天最高 / 全天最低 / 全天成交量，就是未来函数。**
> 这是金融机器学习中最常见、也最致命的自欺欺人方式。回测惊艳、实盘归零，几乎都源于此。

**结论：日 K 线无法支撑真正的"盘中"判断。** 必须二选一：

| 方案 | 决策时点 | 数据需求 | 难度 | 建议 |
|------|---------|---------|------|------|
| **方案 1** | **今日开盘前**（或以开盘价成交） | 仅需日 K 线，只用到**昨收及之前**的完整数据 | 中 | ✅ **先做这个** |
| **方案 2** | 盘中任意时刻（如 14:00） | 需**分钟级数据**，构造"当日截至 T 时刻的部分 bar" | 高 | 方案 1 成功后再升级 |

**路线：先用方案 1 把无泄漏的完整流程跑通（约 4 个月），再升级方案 2。**
方案 1 的全部代码（特征、标签、验证、评估）在方案 2 中可 90% 复用，不是弯路。

---

### 1.2 你的数据量比想象中小得多

| 口径 | 行数 | 有效性 |
|------|------|--------|
| 单一指数 20 年 | ≈ 4,850 个交易日 | **不是大数据** |
| 其中"市场级转折点"（若占 3%） | ≈ **145 个正样本** | 严重不足 |
| 全市场 5000 股 × 4850 天 | ≈ 2,400 万行 | 行数虚高 |

> 🚨 **A 股同涨同跌，横截面相关性极高。** 5000 只股票在同一天的涨跌**不是 5000 个独立样本**，
> 有效独立信息量可能仅相当于几百个"市场级事件"。

**应对**：
- 用**面板数据**扩充（多个指数 + 行业指数 + 个股），但评估时**不可**按行数计算置信度
- 交叉验证必须**按时间分组**，同一天的所有样本必须在同一折内（避免同日样本跨折泄漏）
- 优先使用**指数**（沪深300、中证500、上证综指）起步：噪音小、无个股特殊事件、无退市问题

---

### 1.3 A 股的规律会随制度变迁而失效

20 年跨度内制度发生了根本变化：

| 时间 | 事件 | 影响 |
|------|------|------|
| 2005–2007 | 股权分置改革、大牛市 | 市场结构完全不同 |
| 2008 | 全球金融危机、暴跌 | 极端 regime |
| 2010-04 | 沪深300股指期货推出 | 首次可系统性做空 |
| 2015 | 杠杆牛市 + 股灾 | 极端 regime，杠杆行为主导 |
| 2016-01 | 熔断机制实施 4 天即暂停 | 结构断点 |
| 2019-07 | 科创板开市，涨跌幅 ±20% | 交易规则分化 |
| 2020-08 | 创业板改为 ±20% | 同上 |
| 2019 至今 | 机构化、注册制、外资占比上升 | 微观行为改变 |

> 🚨 **2006 年的规律对 2026 年可能完全无效（概念漂移）。**

**应对**：
- **必须**留出最近 2–3 年作为**从未参与任何调参的最终样本外数据**
- 分段检验：模型在 2010–2014 / 2015–2018 / 2019–2022 / 2023–至今 各段表现如何？
- **若模型只在早期有效、近年失效 → 视为失败**，不可用整体平均值掩盖
- 考虑只用近 8–10 年数据（近期数据更相关，虽然样本更少 —— 这是一个真实的权衡）

## 2. 数据方案

### 2.1 数据源（免费，Python 可直接调用）

| 库 | 用途 | 特点 |
|----|------|------|
| **akshare** | 日线、指数、基本面 | 免费开源、接口全、无需注册 |
| **baostock** | 日线 + **5/15/30/60 分钟线**、复权因子 | 免费、含分钟数据，方案 2 必备 |
| tushare | 全面 | 需积分权限 |

> 建议：**方案 1 用 akshare，方案 2 提前用 baostock 下载分钟数据备用**（分钟数据量大，越早开始积累越好）。
> 接口会变动，使用前请查阅当时的官方文档。

### 2.2 复权处理 —— 一个隐蔽的泄漏点

- 计算收益率**必须**使用复权价，否则除权除息日会出现虚假的暴跌
- 🚨 **"前复权"价格会随未来的分红送股而改变** → 用今天下载的前复权数据回测 2015 年，
  等于把 2015 年之后的信息塞进了 2015 年的价格里，**这是未来函数**
- **正确做法**：使用**后复权**价格，或使用"复权因子 + 当时点还原"的方式

### 2.3 数据清洗要点

- **停牌**：长期停牌形成数据空洞，不可简单前向填充后计算收益率
- **幸存者偏差**：若只取当前存在的股票，已退市的被排除 → 结果系统性偏乐观
- **ST 股**：涨跌幅限制不同（±5%），需单独标记
- **交易日历**：必须用真实交易日，不可用自然日 `resample`
- **异常值**：新股上市初期、重大资产重组复牌后的极端波动

## 3. A 股特有的执行层陷阱（决定模型有没有用）

### 3.1 T+1 制度造成的方向不对称 ⭐ 重要

**当日买入的股票，次日才能卖出。**

| 信号 | 可否当日执行 | 说明 |
|------|------------|------|
| **下跌转折点**（卖出/减仓） | ✅ 可以（若持仓非今日买入） | 信号价值直接可兑现 |
| **上涨转折点**（买入/加仓） | ⚠️ 买入后被锁定至次日 | 承担一夜隔夜风险 |

> 💡 **战略建议：优先攻"下跌转折点"（风险预警）。**
> 理由：① T+1 下可当日执行 ② 规避损失的确定性收益高于追逐利润
> ③ 下跌往往伴随波动率放大，信号特征更显著、更易被模型捕捉。
>
> 这比"两个方向都要预测"务实得多，也更容易做出成果。

### 3.2 涨跌停 —— 信号无法执行

- 主板 ±10%，ST ±5%，创业板/科创板 ±20%
- **涨停时买不进，跌停时卖不出** → 模型在最需要行动时恰好无法行动
- 回测**必须**排除涨跌停时点的成交假设，否则收益虚高

### 3.3 交易成本

| 项目 | 费率（约） |
|------|-----------|
| 佣金 | 万分之 2.5 左右，有最低收费 |
| 印花税 | 0.5‰（**仅卖出**，2023 年下调后） |
| 过户费 | 0.001‰ 级别，双向 |
| **往返合计** | **约 0.1% 量级** |

> 🚨 高频翻转的策略会被成本吃掉。**任何回测必须扣除成本后再评估。**
> 若信号只能捕捉 0.3% 的波动，扣成本后基本无意义。

### 3.4 滑点与流动性

以收盘价成交是回测的常见幻觉。实际成交价会有滑点，指数需通过 ETF 交易。

## 4. 重新定义问题

### 4.1 决策时点定义（方案 1）

```
在第 t 日开盘前做决策
  可用信息：截至第 t-1 日收盘的全部完整日 K 线
  绝不可用：第 t 日的任何数据（含开盘价，除非假设以开盘价成交）
```

代码层面的铁律：所有特征构造完成后，**统一 `shift(1)`**，从机制上杜绝泄漏。

### 4.2 标签设计（三种，由易到难）

#### 标签 A —— 三分类方向（推荐起点）

```python
未来 N 日累计收益 > +阈值   → 上升 (1)
未来 N 日累计收益 < -阈值   → 下降 (-1)
其余                        → 盘整 (0)
```

- `N` 建议先取 3 或 5（1 日噪音过大，20 日太远）
- 阈值建议用**波动率自适应**（如 1.0 × 近 20 日日波动率 × √N），而非固定百分比
- "盘整"类是关键：让模型只在有把握时表态

#### 标签 B —— ZigZag 摆动点标注（贴近"转折点"本义）

用阈值法回溯标注历史高低点：从高点回撤超过 x%（如 5%）即确认前高为转折点。
再定义：当前时点是否处于转折点前后 ±k 日内。

- 优点：真正对应"趋势转折"的直觉
- 缺点：正样本极少（可能 2–3%），属**极度不平衡分类**

#### 标签 C —— 三重障碍法（Triple Barrier）

同时设置止盈线、止损线、时间上限，看哪个先被触及。
优点：天然包含风险收益比与持有期，最贴近真实交易。进阶后采用。

> ⚠️ 标签定义使用未来信息是**合法的**（这是标签的本质）；
> 但**特征中绝不可含未来信息**。二者必须严格分离。

### 4.3 特征设计（全部基于 t-1 及之前）

| 类别 | 具体特征 |
|------|---------|
| 收益动量 | 1/3/5/10/20/60 日收益率 |
| **趋势二阶变化** ⭐ | 5 日斜率 − 前 5 日斜率；动量的差分；均线间距的变化速度 |
| 均线关系 | 收盘/MA5、MA5/MA20、MA20/MA60 的比值及其变化 |
| 波动率 | 5/20/60 日已实现波动率；**波动率的变化率**（转折常伴随波动放大） |
| 位置 | 当前价在过去 20/60/250 日区间中的百分位；距 250 日最高点的回撤幅度 |
| 量价 | 成交量比（当日量/20 日均量）、量的变化率、量价背离（价涨量缩） |
| K 线形态 | 实体/影线比例、连续同向天数、跳空 |
| 极值距离 | 距上一个 ZigZag 高/低点的天数与幅度 |
| 市场宽度 | 上涨家数占比、涨跌停家数（需全市场数据） |
| 跨市场 | 大小盘强弱（沪深300 vs 中证500）、行业轮动 |
| 日历 | 星期、月份、是否临近长假 |

> 💡 **核心洞察：转折信号藏在"二阶变化"里。**
> 不是"在涨"，而是"**涨得越来越慢**"——斜率衰减、动量减弱、波动率突变。
> 这是本方案最重要的特征设计原则。

## 5. 验证方案（金融场景比常规 ML 严苛得多）

### 5.1 划分方式

```
训练期      验证期(调参)      最终样本外(只测一次)
2010—2018   2019—2022        2023—至今
```

- **Walk-forward 滚动回测**：每年重训一次，模拟真实滚动使用
- **Purged & Embargo**：因标签使用了未来 N 日数据，训练集末端必须**剔除**与验证集重叠的 N 天，
  并留出隔离带（embargo）—— 否则标签重叠造成泄漏
- 同一日的所有横截面样本必须在同一折内

### 5.2 必须对比的基线

| 基线 | 说明 |
|------|------|
| 永远预测"盘整" | 不平衡数据下的准确率上限陷阱 |
| 随机漫步（明日=今日） | 有效市场的零假设 |
| 趋势延续（动量） | 最朴素的有效策略 |
| 均线交叉（如 MA5/MA20） | 传统技术指标基准 |
| **买入并持有** | 策略必须扣成本后战胜它，否则无意义 |

> 🚨 **打不过这些基线，模型即无价值。** 这一条能省下几个月无用功。

### 5.3 评估指标（不要看准确率）

**分类层面**
- 精确率 / 召回率 / F1（针对"下跌转折"这一稀有正类）
- AUC —— 金融上 **0.53–0.57 已属可用**，> 0.65 请立即排查泄漏
- 概率分层单调性：按预测概率分 5 档，实际未来收益是否单调递减？（**比 AUC 更实用**）

**执行层面（更重要）**
- **确认延迟**：信号发出时距真实转折已过几日？
- **扣除成本后**的策略收益、最大回撤、夏普比率、卡玛比率
- 信号触发频率（过于频繁 → 成本吞噬）
- 分年度表现稳定性（近年是否失效）

## 6. 现实的成功标准

| 指标 | 及格线 | 说明 |
|------|--------|------|
| AUC | 0.54 – 0.58 | 超过 0.65 请优先怀疑泄漏 |
| 下跌转折精确率 | 55% – 60% | 已具备实用价值 |
| 确认延迟 | ≤ 2–3 日 | 太晚则无意义 |
| 概率分层 | 单调 | 比 AUC 更能说明真实性 |
| 近 3 年表现 | 不明显衰减 | 硬性要求 |
| 扣成本后 | 优于买入持有 | 最终检验 |

### 心法

1. **追求"有用"，不追求"神准"**：60% 精确率 + 提前 2–3 日，已经很有价值
2. **让模型做"报警器"，不做"决策者"**：输出"今日下跌转折风险 = 0.73"作为辅助信号，
   与你自己的业务判断结合。这比追求全自动更靠谱，也更能发挥你的经验优势
3. **优先做风险预警，而非收益预测**：契合 T+1 制度，且规避损失的确定性更高
4. **不要用真金白银验证未成熟的模型**

## 9. 立即可做的第一步

**建议先做"数据地基 + 无泄漏框架"，而非急于建模。**

具体产出：
1. `src/data.py` —— akshare 取沪深300 日线，后复权，缓存为本地文件
2. `src/features.py` —— 生成上述特征，**统一 shift(1)**，附带泄漏自检断言
3. `src/labels.py` —— 标签 A（波动率自适应阈值三分类）
4. `src/validate.py` —— 时序切分 + purge/embargo + 基线对比
5. `notebooks/01_探索.ipynb` —— 画图核对数据是否正确

> 只要这套地基是干净的，后面换模型、换特征都是几行代码的事。
> 地基脏了，后面所有结论都是假的。

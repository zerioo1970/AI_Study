## 1. 术语纠正：不是「河流图」

> ⚠️ 本节结论已被 **8.1 节部分修正**：若用途是"看一族的组合力"而非比较单个指标，
> 河流图（改为双向堆叠形态）是合适的。

| | **河流图 / 主题河流图**<br>(Streamgraph / ThemeRiver) | **热力图**<br>(Heatmap) |
|---|---|---|
| 数值编码 | **条带厚度** | **颜色深浅** |
| 纵轴含义 | 堆叠累加，基线流动 | 每行一个指标，位置固定 |
| 适用 | 展示构成比例随时间变化 | 展示矩阵随时间变化 |

**对本项目必须使用热力图，不可用河流图。** 三个理由：

1. **基线漂移（baseline distortion）** —— 堆叠图中上层指标的位置会被下层波动推动。
   指标数值未变但视觉上上下跳动，跨指标、跨时间的比较在视觉上失效。
2. **厚度比颜色更难读** —— 人眼判断细带厚度的精度远低于判断颜色，150 条带尤甚。
3. **喂给模型时河流图是失真的** —— 河流图渲染成像素后是经过非线性变形的数据；
   热力图是**原始矩阵的直接映射**，信息保真。

### 正确的叫法

- **特征矩阵 / 时间-特征热力图**，形状 = `[150 指标 × N 天]`
- 信号处理中的同类图：**语谱图 / 频谱图（spectrogram）**
- 研究方向名称：**时间序列图像化（Time Series Imaging, TS2I）**

> 学术上常见的 GAF（Gramian Angular Field）、MTF、递归图（RP）都是把**单变量**序列变成图。
> 本项目有 150 个变量，`[通道 × 时间]` 的直接排布**更自然、信息更无损**，
> 无需改用 GAF。这一步的选择是正确的。

## 2. 🚨 两个高度可疑的泄漏（最高优先级排查）

### 泄漏 1：归一化是否用了全历史范围？

```python
# ❌ 全历史归一化 = 未来函数
z = (x - x.mean()) / x.std()
z = (x - x.min()) / (x.max() - x.min())

# ✅ 因果归一化（滚动窗口，只用当前时点之前）
z = (x - x.rolling(250).mean()) / x.rolling(250).std()
```

> 若用全历史归一化，则 2010 年某一天的数值里**含有 2025 年极值的信息**。
>
> 且这对视觉也有实际影响：**全局归一化的图看起来更漂亮整齐 —— 恰恰因为它偷看了未来。**

### 泄漏 2：150 个指标是在全部数据上筛选的？⭐ 更隐蔽

若"选出贡献最大的 150 个"这一步用了全部 20 年数据，则测试集的信息
**已通过"哪些指标被选中"这个决策**泄漏进来。

> 这叫 **特征选择偏差（feature selection bias）**。
> 可怕之处在于：**留出测试集也发现不了**，因为测试集本身参与了特征选择。

**正确做法（二选一）**
- 特征选择放在**每一折的训练集内部**独立进行
- 或只用**最早一段数据**（如 2006–2015）筛选，之后**永久冻结**，不再回头修改

**立即可做的检验** ⭐
> 用 2010–2018 选一次特征排名，再用 2019–2025 单独选一次。
> **若两次的"最重要指标"差别很大 → 筛选结果基本是噪音，不是真实规律。**
>
> 半小时可完成，能直接判断那 150 个指标是否可信。

## 3. 150 个指标高度共线的问题

150 个指标**全部派生自同一份 OHLCV**，不是 150 个独立信息源，
真实独立维度可能仅 **10–20 个**。

**后果**
- 同族指标（各周期 RSI、各种均线偏离度…）**互相抢功劳**
- 特征重要性排名**极不稳定**，换随机种子就变
- 因此"选出贡献最大的 N 个"本身不可靠

**应对：相关性层次聚类**，把 150 个分为 20–30 族，每族选代表或做组级重要性（group SHAP）。

💡 **顺带解决可视化问题**：热力图的**行顺序必须按聚类排列**。
随机顺序的热图看不出结构；聚类排序后同族指标相邻，
**"条带"结构才会真正显现**，肉眼才能看出"某一整族指标同时变色"。

## 4. 核心建议：热力图当「诊断仪表盘」，不当模型输入

### 4.1 为什么不建议直接上 CNN

| 本项目数据 | CNN 的需求 |
|---|---|
| 4,850 天，转折点正样本约 **145 个** | 通常需数千至数万样本 |
| 单张图 150×N | 即使很小的 CNN 也有上万参数 |

> **145 个正样本训 CNN → 必然背下训练集。** 这不是调参能解决的。

研究印证：
- 有基准显示 Transformer 类模型在**每类训练样本很少**的数据集上表现不佳
- "理性检验"类研究发现，**表格模型在 UCR/UEA 基准中相当比例的数据集上能超过 ROCKET 家族**
  （约 19% 单变量 / 28% 多变量数据集）→ 说明"表格化 + GBDT"绝非低级方案

来源：[多通道时序分类可视化研究](https://www.mdpi.com/2813-2203/5/1/15) ·
[A Sanity Check on Modern Time Series Classification Algorithms](https://arxiv.org/pdf/2308.07886)

### 4.2 热力图的正确用法：四轨道对照面板

```
┌────────────────────────────────────┐
│  热力图 [150 指标 × 时间]            │  ← 行按相关性聚类排序
├────────────────────────────────────┤
│  价格走势                            │
├────────────────────────────────────┤
│  真实转折点（事后标注）               │
├────────────────────────────────────┤
│  模型输出的转折概率                   │
└────────────────────────────────────┘
```

**四者对照，可一眼看出模型在哪些转折上抓到了、哪些漏了、哪些误报。**

### 4.3 更值得做：SHAP 热力图 ⭐ 金矿

同样是 `[150 指标 × 时间]` 布局，但**颜色 = SHAP 值**
（该指标在该天对预测的贡献）。

> 可直接看到：**模型在什么时候、依赖哪些指标做出判断。**
> 比静态的"特征重要性排名"信息量大得多，且完全符合视觉直觉。

> **结论：人眼在这里的正确用途是"审查模型判断"，而不是"替代模型判断"。**

## 5. ⚠️ 风险提示：「看起来挺有用」是危险信号

> **人眼极善于在噪音中发现模式**（空想性错觉 / apophenia）。
>
> 能在历史图上"看出"转折前的征兆，很可能是因为**已经知道那里是转折点**。
> 这是后见之明，不是预测能力。

### 检验方法：盲测 ⭐ 现阶段性价比最高的一件事

1. 随机挑 50 个时间点
2. 每次**只显示截止那一天为止**的热力图，后续走势完全遮住
3. 判断"这里是不是下跌转折点"，记录答案
4. 全部做完后揭晓，统计准确率与误报率

**判读**
- 显著高于随机基准（注意转折点稀少，基准很低）→ **视觉方法确实含信息，值得做成模型**
- 不显著 → 是后见之明，及时止损

> 不需要任何机器学习即可验证这套方法有无真信号，且本身就是很好的 Matplotlib 练习。

## 6. 若确实要用「卷积 / 形状」思想 → 用 ROCKET，不用 CNN

### ROCKET / MiniRocket / MultiRocket

**原理**：大量**随机卷积核**提取特征 + 一个**线性分类器**。
捕捉卷积能捕捉的形状信息，但只需训练线性层。

| | CNN | ROCKET 家族 |
|---|---|---|
| 需训练参数 | 上万~百万 | **仅线性层** |
| 训练速度 | 慢 | **快几个数量级** |
| 小样本稳健性 | 差 | **好得多** |
| 多变量支持 | 是 | 是 |

- MultiRocket 比 MiniRocket 更准，可与顶级方法（HIVE-COTE 2.0）竞争，同时快几个数量级
- 有基准显示 ROCKET 在多数据集上精度最稳定
- 库：`sktime` / `aeon`

### ⚠️ 对本项目的具体警告

> 同一基准发现：**ROCKET 性能会随通道数非常多而下降。**
> **本项目有 150 个通道 —— 正好落在这个弱点上。**

→ 必须先做特征聚类降到 20–30 个代表，再考虑 ROCKET（与第 3 节是同一件事）。

来源：[ROCKET 原论文](https://ar5iv.labs.arxiv.org/html/1910.13051) ·
[MultiRocket](https://arxiv.org/pdf/2102.00457v2.pdf) ·
[多通道时序分类基准](https://www.mdpi.com/2813-2203/5/1/15)

## 8. 补充（v1.1）：双通道编码与「气泡块」直觉的量化

> 用户澄清：**并非真要喂给 CNN，而是借用 CNN 的原理**（局部共激活检测）；
> 计划用「颜色 + 大小」双通道编码热力图，把相关指标排在一起，
> 观察"一族气泡同时鼓起变红、另一族缩小变蓝"；河流图同理，把趋势相近的层排在一起看组合力。
> 路线是**先人眼验证假设，成立后再自动化**。

### 8.1 对第 1 节结论的修正

第 1 节对河流图"基线漂移"的批评**只在需要比较单个指标时成立**。
若用法是"把趋势相近的指标排在一起，看一整族的总厚度变化"，
则**堆叠恰恰是优点** —— 族内累加的总厚度正是要看的"合力"。

**修正结论：河流图对「看组合力」是合适的**，但应改为双向堆叠形态（见 8.4）。

### 8.2 术语对照

| 用户描述 | 术语 |
|---|---|
| 每个点用颜色 + 大小两种方式表示 | **双通道编码 / 气泡矩阵（bubble matrix）** |
| 把相关的指标调整到一起 | **序列化排序（seriation）/ 双向聚类（biclustering）** |
| 一片气泡同时鼓起变红 | **块状共激活（coherent block activation）** |
| 借用 CNN 的原理 | **局部感受野 + 共激活检测** |
| 红色向上、蓝色向下的对抗 | **双向堆叠图（diverging stacked area）** |

> "考虑 CNN 的原理"这个直觉很准：**CNN 第一层本质就是检测局部共激活。**
> 而用领域知识**手工分组 = 人工设计卷积核**。
> 关键优势：人工设计的核**不需要数据去学**，
> 在仅约 145 个正样本的条件下**比随机初始化的 CNN 更有效、更省数据**。
> 这实际上绕过了 CNN 最大的短板。

### 8.3 ⭐ 核心：把「看气泡」的直觉量化

设第 `t` 日、第 `g` 族含 `n` 个指标，每指标的**因果 z-score** 为 `z`（已按方向统一，正 = 看涨）：

| 眼睛看到的 | 数学表达 | 含义 |
|---|---|---|
| 气泡的**大小与颜色** | `S = mean(z)` | **族强度** |
| 气泡的**整齐程度** | `C = abs(mean(sign(z)))` | **族一致性**（全红=1，红蓝混杂=0） |
| 气泡的**参差不齐** | `D = std(z)` | **族内分歧** |
| 红族 vs 蓝族的**对抗** | `S_看涨 − S_看跌` | **跨族分化** |
| 气泡**鼓到最大后开始瘪** | `ΔC = C(t) − C(t−5)` | ⭐ **一致性的二阶变化** |

**最后一行与本项目核心洞察完全一致**（转折信号藏在二阶变化里 —— 不是"在涨"，
而是"涨得越来越慢"）。它是该洞察在**多指标一致性**维度上的版本：

```
转折点假设 = 一致性 C 处于历史高分位  且  ΔC 开始转负
           （气泡鼓到最大了）        （开始瘪了）
```

> **这可以直接写成 LightGBM 特征 —— 视觉直觉由此变为可计算量。**

特征规模：20–30 族 × 4 个统计量 = 80–120 个特征。
虽仍不少，但比 150 个原始指标**更有结构、更稳定、共线性更低**。

### 8.4 金融领域的理论支撑

| 概念 | 说明 |
|---|---|
| **Breadth（广度）** | 有多少成分在同向运动 |
| **Dispersion（离散度）** | 成分之间的分歧程度 |
| **Divergence（背离）** | 价格还在涨，但指标不跟了 |

> 被广泛观察到的现象：**趋势中段指标高度一致，趋势末端开始出现分歧。**
> 即"**一致性本身的变化**"就是转折信号 —— 正是用户想在图上看的东西。
>
> 结论：这不是凭空想象的视觉模式，而是在试图捕捉**真实存在的结构现象**。

### 8.5 具体画法：两张图互补，不必二选一

#### 图 A：气泡矩阵（看结构）

**大小与颜色应编码两个不同的量**，否则冗余：

| 视觉通道 | 编码 | 理由 |
|---|---|---|
| **大小** | `abs(z)` 强度 | 大 = 信号强 |
| **颜色** | 方向（红涨 / 蓝跌） | 一眼看方向 |

→ "一大片大红气泡" = 这一族强烈看涨且高度一致。

⚠️ **密度问题**：150 指标 × 60 天 = 9000 个气泡，眼睛看不过来。
→ 必须先聚类降到 20–30 族再画。

实现：Matplotlib `scatter(x=日期, y=族序号, s=强度, c=方向)`。

#### 图 B：双向堆叠河流图（看合力）⭐ 对原方案的关键改进

```
        ↑ 看涨族向上堆叠（红）
────────┼──────────────────  ← 零线（固定）
        ↓ 看跌族向下堆叠（蓝）
```

优点：
- "一部分扩大、一部分缩小"变成**上下两块面积的直接对抗**
- 转折点表现为**上下面积交叉 / 反转**，极其直观
- **零线固定 → 无基线漂移问题**

> 该改进保留河流图的全部优点，同时消除第 1 节担心的缺陷。

**分工**：图 A 看**结构**（哪些族在动）；图 B 看**合力**（总体力量对比）。

### 8.6 排序必须用层次聚类，不可手工

**不要手工把"趋势相近的层调在一起"**，原因：

1. 手工排会不自觉地**按已知答案去排** → 又是后见之明
2. 手工排法**无法复现**，也无法在新数据上重做

**用相关性层次聚类自动排序**（`scipy.cluster.hierarchy`）：
自动把相关指标排在一起、给出族划分、**可复现、可在训练集内独立完成**（避免特征选择泄漏）。

⚠️ 相关性矩阵也必须用**训练期数据**计算，不可用全历史。

### 8.7 人眼阶段的正确定位

| 阶段 | 人眼可行性 |
|---|---|
| **验证假设**（这套视觉方法有无信号） | ✅ 可以，且必须靠人眼 |
| **发现特征**（什么气泡模式最有预示性） | ✅ 可以 |
| **每天判断 5000 只股票、2 分钟内完成** | ❌ 绝对不行 |

> **人眼负责"发现规律"与"确认规律存在"；机器负责"规模化执行"。**
> 8.3 节的量化指标是**把眼睛看到的东西交给机器的桥梁**。

### 8.8 方法论肯定

**"先用人眼验证假设，确认有效后再自动化"是正确且专业的做法**，
业界称为 **human-in-the-loop 特征发现**。

优于常见做法（一上来把 200 个特征扔进模型、调参到 AUC 好看、
不知道模型在干什么、上线即崩）。

> **顺序应保持：先理解现象 → 再量化 → 再自动化。**

| 100+ 种指标的生成代码/逻辑 | ⭐ 最有价值 | 保留，是特征工程的起点 |
| `[指标 × 时间]` 的矩阵组织方式 | ⭐ 方向正确 | 保留，就是标准的多变量表示 |
| 视觉化审查的思路 | ⭐ 正确但需改定位 | 从"模型输入"改为"诊断工具" |
| 150 个指标的筛选结果 | ⚠️ 可能不可靠 | 需做泄漏排查与稳定性检验后再用 |
| 归一化处理 | ⚠️ 可能泄漏 | 需改为滚动/扩展窗口 |

> 需要修的是**流程**（归一化方式、筛选时机），不是**思路**。

## 10. 补充（v1.2）：关于早期的 3D 可视化设想，与「周期维度」这块金子

> 用户提到最早曾设想用 C# + 3D 编程把 150 个指标放在一个空间里排开，
> 从前后左右上下不同角度观察其形成的条带；后因
> ①「3D 用计算机提取规则比较麻烦」②「可以简单叠加成河流图」而放弃。

### 10.1 结论：放弃是对的，但理由 ② 需要修正

| 用户判断 | 评价 |
|---|---|
| 放弃 3D | ✅ **正确** |
| 理由 ①：3D 难提取规则 | ✅ **完全正确**，还可补三条 |
| 理由 ②：可简化成河流图 | ⚠️ **需修正**（见 10.3） |
| **被一起扔掉的东西** | ⭐ **「周期 / 时间尺度」是真正的第三维，应救回来** |

### 10.2 3D 在数据分析中是公认反模式

| 问题 | 说明 |
|---|---|
| **遮挡（occlusion）** | 后面数据被前面挡住；150 个指标必然大面积互遮 |
| **透视失真** | 同样大小的物体远的看起来小 → **无法定量比较** |
| **深度感知精度极差** | 人眼判断深度位置的精度远低于判断平面位置与颜色 |
| **必须旋转才能理解** | → 不可复现、无法截图沉淀、无法批量扫描 |

最后一条对本项目尤其致命：目标是**收盘前 2 分钟扫描 5000 只股票**，
3D 图连"截一张可沉淀的图"都做不到。

### 10.3 ⭐ 更根本的原因：这份数据本来就没有第三个维度

数据结构是 `[150 指标 × N 天]`，**本质二维**。
画成 3D 时，第三个轴（高度 = 数值）只是**把"颜色 / 大小"换成了"高度"**。

> **3D 并没有增加信息维度，只增加了视觉负担。**

因此准确的说法不是"3D 可以简化成河流图"（这暗示有信息损失），而是：

> **3D 从一开始就没有比 2D 多装任何东西。没有损失，只是甩掉了包袱。**

这也解释了为何换成热力图/河流图后感觉"够用" —— **不是妥协，是回到了正确的表示。**

### 10.4 ⭐⭐ 但 3D 直觉里有一块金子：维度选错了

"想要第三个维度"的冲动可能是对的，只是轴选错了。

**关键问题：150 个指标里有多少是「同一指标的不同周期」？**

典型情况：
```
RSI-6, RSI-12, RSI-24
MA偏离-5, MA偏离-10, MA偏离-20, MA偏离-60
波动率-5, 波动率-20, 波动率-60
```

若如此，则数据的**真实结构其实是三维的**：

```
[指标类型 × 周期参数 × 时间]    ← 这才是天然的三维
```

> **想要的第三维不是"数值高度"，而是"时间尺度"。**
> 这个维度**真实存在且独立**，不是把颜色换成高度。当年的直觉抓到了东西，只是没找对轴。

### 10.5 周期维度对判断转折点特别重要

同一族指标在不同周期上的差异**本身就是转折信号**：

| 现象 | 含义 |
|---|---|
| **短周期已转，长周期未转** | ⭐ **早期转折信号（最有价值）** |
| 全周期同时转向 | 强烈确认，但很可能**已经晚了** |
| 短周期反复摇摆，长周期稳定 | 噪音，不是转折 |
| 长周期先转、短周期跟随 | 罕见，通常是数据问题 |

术语：**信号的期限结构（term structure）** / **多尺度一致性**。

#### 可量化（延续 8.3 节）

| 量 | 公式 | 含义 |
|---|---|---|
| **尺度分化** | `S_短周期 − S_长周期` | 短长背离程度 |
| **传导时滞** | 短周期转向后几天长周期跟上 | 转折传播速度 |
| **短周期领先度** | `C_短 − C_长` | 是否处于"早期" |

**结合 8.3 节，转折假设可写得更完整：**

```
早期下跌转折信号 =
    短周期族一致性 已转负
  且 长周期族一致性 仍为正但 ΔC < 0     ← 长周期开始松动
  且 尺度分化 处于历史极端分位
```

> 即"**短周期先塌，长周期开始跟着松**" —— 正对应视觉上"气泡从一头开始瘪"。

### 10.6 正确做法：小倍数图（small multiples），不是 3D 立体图

```
     短周期(5日)       中周期(20日)      长周期(60日)
   ┌────────────┐   ┌────────────┐   ┌────────────┐
   │  气泡矩阵   │   │  气泡矩阵   │   │  气泡矩阵   │
   │ [族 × 时间] │   │ [族 × 时间] │   │ [族 × 时间] │
   └────────────┘   └────────────┘   └────────────┘
```

| | 3D 立体图 | 小倍数图 |
|---|---|---|
| 遮挡 | 严重 | 无 |
| 定量比较 | 不可能 | 容易 |
| 可截图沉淀 | 否 | 是 |
| 可批量生成 | 难 | 容易 |
| **看"短周期先转"** | 要旋转半天 | **一眼看出** |

> 通用经验：**想加第三个维度时，答案通常是"多画几张 2D 图"，而不是"画一张 3D 图"。**

### 10.7 关于用 C# 做可视化

技术上可行（WPF / Unity / OpenTK），但**不建议**：

| 用途 | 建议语言 |
|---|---|
| **探索、试错、画图** | **Python**（Matplotlib 生态成熟，几行出图，试错成本极低） |
| **最终生产系统 / 与现有系统对接** | **C#**（用户强项，发挥在此） |

与既定路线一致：**Python 训练与研究 → 暴露成 API → C# 系统调用。**

> 探索阶段用 C# 写可视化，会有 80% 时间花在画图代码上；Python 里这个比例是反过来的。

### 10.8 「从不同角度观察」的正确满足方式

- **交互式 2D + 时间滑块** —— 拖动时间轴看图案演化，比旋转 3D 有用得多
- **动画** —— 用时间作"第四维"，而非挤进空间轴
- 工具：Matplotlib animation；Plotly（自带缩放/悬停/滑块）；后期可用 Streamlit 加滑块

> "随时间演化"用**动画**表达，远比用第三个**空间轴**表达清楚。

### 10.9 行动补充

| 优先级 | 事项 |
|---|---|
| 🟠 高 | **清点 150 个指标中哪些是"同族不同周期"**，重组为 `[指标类型 × 周期 × 时间]` |
| 🟡 中 | 画小倍数图（按周期分面的气泡矩阵） |
| 🟢 后 | 计算尺度分化、传导时滞、短周期领先度，作为特征 |
| ⚪ 不做 | 3D 立体可视化 |

## 11. 补充（v1.3）：3D 设想的准确形态 —— 曲面图 / 瀑布图

> ⚠️ **本节修正第 10 节的部分论断。** 上一轮误解了用户的 3D 设计。
> 用户的实际设计是**3D 曲面图**：X = 时间（一日一格）、**Y = 指标数值（高度，已归一化）**、
> Z = 150 个指标依次排列。目的是观察波动切面，
> 以及"Z 轴上不同指标的 y 值从远到近 / 从近到远来回波动"。

### 11.1 正名

| 名称 | 说明 |
|---|---|
| **3D 曲面图（surface plot）** | Matplotlib `plot_surface` |
| **瀑布图（waterfall plot）** | ⭐ 信号处理 / 振动分析的经典图形 |
| **山脊图 / 峰峦图（ridgeline / joyplot）** | 它的 **2D 版本**，见 11.6 |

#### 一个有说服力的先例

**振动分析与声学领域走过完全相同的路。** 早年普遍用 3D 瀑布图看
"频率成分如何随时间演化"，但现在：

> **自动化分析几乎全部改用 2D 彩色谱图（spectrogram），3D 瀑布图只留作演示与直观讲解。**

原因与用户自己发现的一致：**3D 直观，但无法让计算机提取规则。**

> 即：**用户的判断不是外行直觉，而是已被其他工程领域验证过的结论。**

### 11.2 修正第 10.3 节：3D 曲面确实有热力图没有的东西

| | 数值编码通道 | 读取精度 |
|---|---|---|
| 热力图 | **颜色** | 低（人眼分辨颜色层次能力有限） |
| 3D 曲面 | **高度** | **高**（人眼读高度/位置最准） |

> 信息量相同（都是 `[指标 × 时间] → 数值`），但**"高度"通道比"颜色"读得更准**。
> 单看一条曲线，3D 曲面确实比热力图清楚。
>
> **第 10.3 节"3D 没有增加任何东西"说得过于绝对，此处修正。**

### 11.3 但 150 条曲线的遮挡会完全抵消该优势

| 曲线数量 | 高度通道是否可用 |
|---|---|
| 1 条 | ✅ 优于颜色 |
| 10 条 | 🟡 尚可，略有遮挡 |
| **150 条** | ❌ **前面的山峰把后面全挡住** |

更麻烦的是：**遮挡随视角变化**。从某角度看到"一片山峰鼓起"，
旋转 30° 可能发现那是前排挡出的假象。

> **原判断仍然成立**：150 指标的 3D 曲面无法可靠提取规则。
> 但原因不是"没信息"，而是"**信息被遮挡，且遮挡取决于视角**"。

### 11.4 ⚠️ 用户提到的一个观察可能是排序的产物

用户观察："下跌转折日时，波动大的比较靠近 Z 轴零轴，波动小的离零很远。"

**需核实：Z 轴当时是否按波动率大小排序？**

若是，则"波动大的靠近零轴"是**排序方式决定的，非数据规律** —— **同义反复（tautology）**。

> 这类错误在数据分析中非常常见：**看到的"规律"其实是自己排列方式的倒影。**

**判别方法（10 分钟）**
- 把 Z 轴改为**随机顺序**重画
- 现象消失 → 来自排序，非数据
- 仍能看到"某一群指标在转折日集中动"（只是位置散开）→ **才是真信号**

### 11.5 ⭐⭐ 但「波沿 Z 轴传播」这个观察是金子

用户观察："在股票价格按日上下波动时，可以看到 Z 轴上不同指标的 y 值
从远到近或从近到远，在 Z 轴来回波动。"

**这描述的是「波沿 Z 轴传播」。其意义完全取决于 Z 轴排序方式：**

| Z 轴排序 | "波沿 Z 传播"的含义 |
|---|---|
| 随机顺序 | ❌ 无意义，纯视觉噪音 |
| 按波动率排 | ⚠️ 同义反复（见 11.4） |
| 按相关性聚类排 | 🟡 有一定意义（同族一起动） |
| **按周期长短排（短→长）** | ⭐⭐ **有明确物理意义** |

#### 若 Z 轴按周期排序

```
Z轴:  RSI-6 → RSI-12 → RSI-24 → MA-5 → MA-10 → MA-20 → MA-60 ...
      ←──── 短周期                            长周期 ────→
```

> **"波从近到远传播" = 信号从短周期向长周期传导。**
>
> 这正是第 10.5 节的**传导时滞 / 信号期限结构**。
> 用户所说的"波在 Z 轴上来回"，按周期排序后即：
> **短周期先动 → 波往长周期方向推 → 长周期跟上**
>
> 而"**波刚从短周期开始往长周期推**"的瞬间，就是**早期转折信号**。

**用户的两个想法（3D 波传播 + 气泡鼓瘪）指向同一个结构 —— 这是好迹象。**

#### 可量化（不必画 3D）

| 量 | 计算方式 | 含义 |
|---|---|---|
| **传导时滞** | 相邻 Z 层之间的**互相关最优时滞** | 波传播速度 |
| **传播方向** | 时滞的符号 | 短→长（正常）or 长→短（异常） |
| **传播强度** | 互相关峰值高度 | 波传得清不清楚 |

> 这三个数即"波沿 Z 轴传播"的数学表达，**可直接作为 LightGBM 特征**。

### 11.6 2D 的答案：山脊图（ridgeline / joyplot）⭐

若舍不得"曲线形状"（热力图确实丢失了它），有一个 2D 图形正好补上：

```
指标1  ────╱╲──────╱╲────
指标2   ───╱─╲────╱──╲───
指标3    ──╱──╲──╱───╲──
指标4     ─╱───╲╱────╲─
   ...    （每条曲线向上偏移一点）
```

**即 3D 瀑布图的 2D 平铺版本。**

| | 3D 曲面 | **山脊图** | 热力图 |
|---|---|---|---|
| 保留曲线形状 | ✅ | ✅ | ❌ |
| 遮挡 | ❌ 严重 | 🟡 轻微可控 | ✅ 无 |
| 定量比较 | ❌ | ✅ | ✅ |
| 可截图沉淀 | ❌ | ✅ | ✅ |
| 可批量生成 | ❌ | ✅ | ✅ |
| 可容纳条数 | ≤10 | **20–40** | 150 |

> **山脊图 = 3D 想法的可用版本。** 保留"波形起伏"与"波沿 Z 传播"的视觉，
> 同时可截图、可批量、可定量。
> 前提仍是：**先聚类降到 20–30 族**，150 条山脊也会糊成一团。

实现：Matplotlib 手工加纵向偏移叠加折线；或用 `joypy`。

### 11.7 四种图各管一件事（工具箱定稿）

| 图 | 看什么 | 可容纳 | 定位 |
|---|---|---|---|
| **气泡矩阵** | 哪些族在动、强不强、齐不齐 | 150（降到 30 更好） | **主力扫描图** |
| **双向堆叠河流图** | 看涨 vs 看跌的总合力 | 不限（分两侧） | **合力对抗图** |
| **山脊图** | **波形形状 + 波沿 Z 传播** | 20–40 | **形态细看图** |
| 3D 曲面 | 直观感受、讲解 | ≤10 | **演示图，不用于分析** |

### 11.8 结论：3D 不是废弃，而是降级为「单案例研究工具」

| 用途 | 3D 曲面 |
|---|---|
| **深度研究单只股票的某段行情**（理解现象） | ✅ 可以，且直观 |
| **给自己或别人讲解"转折时发生了什么"** | ✅ 很好 |
| **批量扫描 5000 只股票** | ❌ 不可行 |
| **让计算机提取规则** | ❌ 不可行 |

> **当年的决定是对的，但不必彻底扔掉。** 把它当偶尔用一次的"显微镜"，
> 而非每天用的"扫描仪"。

若确实要做，建议用 **Plotly**（浏览器内自由旋转缩放，交互体验远好于 Matplotlib，几行代码）。

# 指标热力图与时间序列图像化

> 起因：已自行生成 100+ 种日 K 线指标，筛选出约 150 个对下跌转折点贡献最大的指标，
> 归一化后按「横轴=日期、纵轴=指标」排布成条带图，希望借助视觉/CNN 的方式判断转折点。
>
> 本文档纠正术语、指出流程中的泄漏风险、并给出更适合小样本的替代路线。
> 关联：[A股转折点检测方案](A股转折点检测方案.md) · [决策时点设计](决策时点设计.md) · [技术雷达](技术雷达.md)

## 1. 术语纠正：不是「河流图」

| | **河流图 / 主题河流图**<br>(Streamgraph / ThemeRiver) | **热力图**<br>(Heatmap) |
|---|---|---|
| 数值编码 | **条带厚度** | **颜色深浅** |
| 纵轴含义 | 堆叠累加，基线流动 | 每行一个指标，位置固定 |
| 适用 | 展示构成比例随时间变化 | 展示矩阵随时间变化 |

**对本项目必须使用热力图，不可用河流图。** 三个理由：

1. **基线漂移（baseline distortion）** —— 堆叠图中上层指标的位置会被下层波动推动。
   指标数值未变但视觉上上下跳动，跨指标、跨时间的比较在视觉上失效。
2. **厚度比颜色更难读** —— 人眼判断细带厚度的精度远低于判断颜色，150 条带尤甚。
3. **喂给模型时河流图是失真的** —— 河流图渲染成像素后是经过非线性变形的数据；
   热力图是**原始矩阵的直接映射**，信息保真。

### 正确的叫法

- **特征矩阵 / 时间-特征热力图**，形状 = `[150 指标 × N 天]`
- 信号处理中的同类图：**语谱图 / 频谱图（spectrogram）**
- 研究方向名称：**时间序列图像化（Time Series Imaging, TS2I）**

> 学术上常见的 GAF（Gramian Angular Field）、MTF、递归图（RP）都是把**单变量**序列变成图。
> 本项目有 150 个变量，`[通道 × 时间]` 的直接排布**更自然、信息更无损**，
> 无需改用 GAF。这一步的选择是正确的。

## 2. 🚨 两个高度可疑的泄漏（最高优先级排查）

### 泄漏 1：归一化是否用了全历史范围？

```python
# ❌ 全历史归一化 = 未来函数
z = (x - x.mean()) / x.std()
z = (x - x.min()) / (x.max() - x.min())

# ✅ 因果归一化（滚动窗口，只用当前时点之前）
z = (x - x.rolling(250).mean()) / x.rolling(250).std()
```

> 若用全历史归一化，则 2010 年某一天的数值里**含有 2025 年极值的信息**。
>
> 且这对视觉也有实际影响：**全局归一化的图看起来更漂亮整齐 —— 恰恰因为它偷看了未来。**

### 泄漏 2：150 个指标是在全部数据上筛选的？⭐ 更隐蔽

若"选出贡献最大的 150 个"这一步用了全部 20 年数据，则测试集的信息
**已通过"哪些指标被选中"这个决策**泄漏进来。

> 这叫 **特征选择偏差（feature selection bias）**。
> 可怕之处在于：**留出测试集也发现不了**，因为测试集本身参与了特征选择。

**正确做法（二选一）**
- 特征选择放在**每一折的训练集内部**独立进行
- 或只用**最早一段数据**（如 2006–2015）筛选，之后**永久冻结**，不再回头修改

**立即可做的检验** ⭐
> 用 2010–2018 选一次特征排名，再用 2019–2025 单独选一次。
> **若两次的"最重要指标"差别很大 → 筛选结果基本是噪音，不是真实规律。**
>
> 半小时可完成，能直接判断那 150 个指标是否可信。

## 3. 150 个指标高度共线的问题

150 个指标**全部派生自同一份 OHLCV**，不是 150 个独立信息源，
真实独立维度可能仅 **10–20 个**。

**后果**
- 同族指标（各周期 RSI、各种均线偏离度…）**互相抢功劳**
- 特征重要性排名**极不稳定**，换随机种子就变
- 因此"选出贡献最大的 N 个"本身不可靠

**应对：相关性层次聚类**，把 150 个分为 20–30 族，每族选代表或做组级重要性（group SHAP）。

💡 **顺带解决可视化问题**：热力图的**行顺序必须按聚类排列**。
随机顺序的热图看不出结构；聚类排序后同族指标相邻，
**"条带"结构才会真正显现**，肉眼才能看出"某一整族指标同时变色"。

## 4. 核心建议：热力图当「诊断仪表盘」，不当模型输入

### 4.1 为什么不建议直接上 CNN

| 本项目数据 | CNN 的需求 |
|---|---|
| 4,850 天，转折点正样本约 **145 个** | 通常需数千至数万样本 |
| 单张图 150×N | 即使很小的 CNN 也有上万参数 |

> **145 个正样本训 CNN → 必然背下训练集。** 这不是调参能解决的。

研究印证：
- 有基准显示 Transformer 类模型在**每类训练样本很少**的数据集上表现不佳
- "理性检验"类研究发现，**表格模型在 UCR/UEA 基准中相当比例的数据集上能超过 ROCKET 家族**
  （约 19% 单变量 / 28% 多变量数据集）→ 说明"表格化 + GBDT"绝非低级方案

来源：[多通道时序分类可视化研究](https://www.mdpi.com/2813-2203/5/1/15) ·
[A Sanity Check on Modern Time Series Classification Algorithms](https://arxiv.org/pdf/2308.07886)

### 4.2 热力图的正确用法：四轨道对照面板

```
┌────────────────────────────────────┐
│  热力图 [150 指标 × 时间]            │  ← 行按相关性聚类排序
├────────────────────────────────────┤
│  价格走势                            │
├────────────────────────────────────┤
│  真实转折点（事后标注）               │
├────────────────────────────────────┤
│  模型输出的转折概率                   │
└────────────────────────────────────┘
```

**四者对照，可一眼看出模型在哪些转折上抓到了、哪些漏了、哪些误报。**

### 4.3 更值得做：SHAP 热力图 ⭐ 金矿

同样是 `[150 指标 × 时间]` 布局，但**颜色 = SHAP 值**
（该指标在该天对预测的贡献）。

> 可直接看到：**模型在什么时候、依赖哪些指标做出判断。**
> 比静态的"特征重要性排名"信息量大得多，且完全符合视觉直觉。

> **结论：人眼在这里的正确用途是"审查模型判断"，而不是"替代模型判断"。**

## 5. ⚠️ 风险提示：「看起来挺有用」是危险信号

> **人眼极善于在噪音中发现模式**（空想性错觉 / apophenia）。
>
> 能在历史图上"看出"转折前的征兆，很可能是因为**已经知道那里是转折点**。
> 这是后见之明，不是预测能力。

### 检验方法：盲测 ⭐ 现阶段性价比最高的一件事

1. 随机挑 50 个时间点
2. 每次**只显示截止那一天为止**的热力图，后续走势完全遮住
3. 判断"这里是不是下跌转折点"，记录答案
4. 全部做完后揭晓，统计准确率与误报率

**判读**
- 显著高于随机基准（注意转折点稀少，基准很低）→ **视觉方法确实含信息，值得做成模型**
- 不显著 → 是后见之明，及时止损

> 不需要任何机器学习即可验证这套方法有无真信号，且本身就是很好的 Matplotlib 练习。

## 6. 若确实要用「卷积 / 形状」思想 → 用 ROCKET，不用 CNN

### ROCKET / MiniRocket / MultiRocket

**原理**：大量**随机卷积核**提取特征 + 一个**线性分类器**。
捕捉卷积能捕捉的形状信息，但只需训练线性层。

| | CNN | ROCKET 家族 |
|---|---|---|
| 需训练参数 | 上万~百万 | **仅线性层** |
| 训练速度 | 慢 | **快几个数量级** |
| 小样本稳健性 | 差 | **好得多** |
| 多变量支持 | 是 | 是 |

- MultiRocket 比 MiniRocket 更准，可与顶级方法（HIVE-COTE 2.0）竞争，同时快几个数量级
- 有基准显示 ROCKET 在多数据集上精度最稳定
- 库：`sktime` / `aeon`

### ⚠️ 对本项目的具体警告

> 同一基准发现：**ROCKET 性能会随通道数非常多而下降。**
> **本项目有 150 个通道 —— 正好落在这个弱点上。**

→ 必须先做特征聚类降到 20–30 个代表，再考虑 ROCKET（与第 3 节是同一件事）。

来源：[ROCKET 原论文](https://ar5iv.labs.arxiv.org/html/1910.13051) ·
[MultiRocket](https://arxiv.org/pdf/2102.00457v2.pdf) ·
[多通道时序分类基准](https://www.mdpi.com/2813-2203/5/1/15)

## 7. 行动优先级

| 优先级 | 事项 | 时机 |
|---|---|---|
| 🔴 最高 | **检查归一化是否用了全历史** | 立刻，10 分钟 |
| 🔴 最高 | **检查 150 指标是否在全数据上筛选** | 立刻 |
| 🟠 高 | 前后期特征排名稳定性检验（2010–18 vs 2019–25） | 半小时 |
| 🟠 高 | 相关性聚类，150 → 20–30 族 | 学完 Pandas 后 |
| 🟡 中 | 热力图行按聚类排序 + 四轨道对照面板 | 第 7–8 周（正好练 Matplotlib） |
| 🟡 中 | **盲测 50 次验证视觉直觉** | 第 7–8 周，性价比最高 |
| 🟢 后 | LightGBM + SHAP 热力图 | 阶段 3–4 |
| 🟢 后 | MiniRocket / MultiRocket 作对照模型 | 阶段 5 之后 |
| ⚪ 不做 | 直接训练 CNN | 数据量不允许 |

## 8. 已有资产的价值评估

用户已完成的工作**很有价值，不要推翻**：

| 已有资产 | 评价 | 处理方式 |
|---|---|---|
| 100+ 种指标的生成代码/逻辑 | ⭐ 最有价值 | 保留，是特征工程的起点 |
| `[指标 × 时间]` 的矩阵组织方式 | ⭐ 方向正确 | 保留，就是标准的多变量表示 |
| 视觉化审查的思路 | ⭐ 正确但需改定位 | 从"模型输入"改为"诊断工具" |
| 150 个指标的筛选结果 | ⚠️ 可能不可靠 | 需做泄漏排查与稳定性检验后再用 |
| 归一化处理 | ⚠️ 可能泄漏 | 需改为滚动/扩展窗口 |

> 需要修的是**流程**（归一化方式、筛选时机），不是**思路**。
